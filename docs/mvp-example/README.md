# 빈살롱 — 사내 카페 온보딩 개선안 프로토타입

신규 사용자가 처음 앱을 켠 순간부터 첫 주문 완료까지의 온보딩 경험을 검증하기 위한 클릭 가능한 MVP입니다.
백엔드·로그인·결제 없이 화면 전환과 인터랙션만 구현한 **사용성 테스트용 시제품**입니다.

## 여는 방법

`index.html` 파일을 **더블클릭**하면 기본 브라우저에서 바로 열립니다. (설치·인터넷 불필요)
데스크톱에서 열어도 화면 중앙에 휴대폰 프레임 모양으로 표시되어 모바일 화면처럼 확인할 수 있습니다.

## 화면 구성과 동선

| 순서 | 화면 | 무엇을 하나 | 다음으로 |
|------|------|-------------|----------|
| 1 | **환영 화면** | 서비스 소개, 온보딩 시작 안내 | `시작하기` → 취향 선택 / `나중에 할게요` → 바로 홈 |
| 2 | **선호 음료 선택** | 6개 취향 칩에서 복수 선택 (아메리카노·라떼·디카페인·티·에이드·달콤) | `내 취향 저장하기` → 홈 (뒤로가기 버튼 있음) |
| 3 | **홈 (추천 노출)** | 선택한 취향에 맞춰 추천 음료를 상단에 보여줌 + 이번 주 인기 | 음료 카드나 `+` 버튼 탭 → 주문 완료 |
| 4 | **주문 완료** | 주문 확인, 복지 포인트 할인 영수증, 대기번호 안내 | `홈으로 돌아가기` → 홈 |

핵심 검증 플로우: **환영 → 취향 선택 → 홈(추천 확인) → 음료 주문 → 완료** 를 클릭만으로 완주할 수 있습니다.

### 온보딩 개선 포인트 (이 프로토타입이 담은 가설)
- 취향을 먼저 물어보고 → 홈 첫 화면에서 **"내 취향 기반 추천"** 으로 즉시 되돌려주어 온보딩의 보상을 체감하게 함
- 선택한 취향 문구를 홈 배너에 그대로 노출("‘라떼, 디카페인’ 취향에 맞춰 골랐어요")해 개인화가 반영됐음을 명시
- `나중에 할게요` 경로도 막다른 길 없이 기본 추천으로 홈에 진입 (온보딩 이탈자 배려)

## 이 MVP로 검증할 수 있는 것 / 없는 것

**검증할 수 있는 것**
- 온보딩 단계 수와 순서가 자연스러운지, 이탈 지점은 없는지
- 취향 선택 UI(복수 선택 칩)가 직관적인지
- "취향을 물어본 보상"으로 추천이 즉시 보이는 흐름이 만족스러운지
- 주문 완료까지의 체감 난이도

**검증할 수 없는 것 (의도적으로 생략한 범위)**
- 실제 로그인/회원가입, 결제, 서버 통신, 주문 내역 저장 (새로고침 시 상태 초기화됨)
- 실제 메뉴 데이터·재고·가격 (모두 그럴듯한 더미 데이터)
- 옵션 선택(사이즈·샷 추가·온도), 장바구니 다건 담기, 결제 수단 선택 — 온보딩 플로우 검증에 불필요하여 제외

## 수정 요청 방법

이 파일을 만든 MVP Builder에게 아래처럼 자연어로 요청하면 됩니다. (예시)
- "취향 선택 화면에 ‘원두 강도’ 슬라이더를 추가해줘"
- "주문 완료 화면에 예상 픽업 시간(예: 5분 뒤)을 표시해줘"
- "홈 추천 카드에 실제 음료 사진 느낌의 색 배경을 넣어줘"
- "환영 화면을 2단계 소개(스와이프)로 늘려줘"

기존 화면 구조는 유지하고 요청한 부분만 수정합니다 (이미 진행한 사용성 테스트 결과와 비교할 수 있도록).

## 참고: 해석한 가정

시나리오에 명시되지 않은 부분은 다음과 같이 해석했습니다.
- 서비스명은 가상의 사내 카페 **"빈살롱"** 으로 설정했습니다.
- 사용자 이름은 **"남호"** 님으로 예시 표기했습니다.
- 사내 카페 특성을 살려 **"사내 복지 포인트 30% 할인"** 을 영수증에 반영했습니다.
- 픽업 위치는 **"3층 빈살롱"**, 대기번호는 주문 시 랜덤 생성됩니다.
