오늘 만드는 것 synthesis.md(어피니티 종합본) → persona-journey.md(페르소나 2종 + 저니맵) → 근거 대조 워크시트
이어지는 사례 ① research-synthesis.md → ② persona-journey.md (①의 출력이 ②의 입력이 됩니다)

이 가이드는 강사 없이도 혼자 따라갈 수 있도록 화면에 보이는 순서 그대로 적었습니다. 막히면 각 단계의 "이렇게 나오면 정상입니다" 박스를 먼저 확인하세요.

오늘 할 일 한눈에 보기

이 모듈은 사례 1개가 아니라 두 사례를 잇는 워크플로우를 경험합니다. 이것이 L2의 도달 기준입니다 — "사례집의 사례 2개 이상을 자기 데이터로 재현할 수 있다."

복사해서 쓰세요
원본 인터뷰/설문 파일
      │  (사례 ①: 어피니티 종합)
      ▼
  synthesis.md  ──── 이 파일이 다음 사례의 "입력 데이터"가 됩니다
      │  (사례 ②: 페르소나 + 저니맵)
      ▼
persona-journey.md
      │  (근거 대조)
      ▼
  근거 대조 워크시트 (스테레오타입 누출 점검)

중요: 4단계(근거 대조)에서는 synthesis.md가 아니라 1단계에서 저장한 원본 인터뷰 파일을 검색해서 대조합니다. 원본 파일은 끝까지 폴더에 남겨 두세요.

STEP 1. 폴더와 원본 파일 준비 (실습 0~5분)

  1. 바탕화면이나 문서 폴더에 작업용 폴더를 하나 만듭니다. 예: research-2026-07-앱개편
  2. 지참한 인터뷰 요약·설문 응답을 텍스트 파일로 저장합니다. 두 가지 방식 중 편한 쪽을 고르세요. - 참가자별 파일(추천): P1.txt, P2.txt … 처럼 참가자마다 파일을 나눕니다. (P는 participant, 참여자) - 한 파일: research.txt 하나에 [P1], [P2]처럼 구분선을 넣어 전부 담습니다. - 자동 전사 도구(클로바노트·다글로 등) 텍스트를 그대로 붙여넣어도 됩니다. 화자 표시(진행자:/참여자:)는 지우지 마세요.
  3. 파일을 열어 실명·전화번호·회사명이 남아 있는지 마지막으로 한 번 더 확인하고, 있으면 P1, A사처럼 가립니다.
  4. 이 폴더에서 터미널을 열고 claude를 입력해 Claude Code를 켭니다. - Mac: Finder에서 폴더 우클릭 → "폴더에서 새로운 터미널 열기" - Windows: 폴더를 열고 주소창에 cmd 입력 → Enter

💡 이렇게 나오면 정상입니다: claude 실행 후 폴더 접근을 허용할지 묻는 창이 뜹니다. "예" 계열 선택지를 고르면 됩니다. 이 창이 안 뜨면 이미 이전 모듈에서 허용해 둔 것이니 그대로 진행하세요.

💡 함정: 파일을 폴더가 아니라 바탕화면에 흩어 두면 Claude Code가 못 찾습니다. 반드시 터미널을 연 그 폴더 안에 파일이 있어야 합니다.

STEP 2. 사례 ① — 어피니티 종합 실행 (실습 5~20분)

아래 프롬프트를 복사해 붙여넣고, { } 부분만 자기 상황으로 바꾸세요. (원문: research-synthesis.md 2단계)

참가자별 파일(P1.txt…)을 만든 경우:

복사해서 쓰세요
이 폴더의 P1.txt ~ P{n}.txt 파일을 모두 읽어줘. {우리 앱 재구매 경험}에 대한 심층 인터뷰 {n}명의 녹취록/요약이야.

어피니티 다이어그램 방식으로 종합해줘. 순서는 이렇게:

1. 먼저 참가자들의 발언에서 의미 있는 조각(한 문장 단위의 관찰·불편·바람)을 뽑아줘. 진행자 질문 말고 참여자 발언만.
2. 비슷한 조각끼리 묶어서 그룹을 만들어줘. 그룹 이름은 미리 정하지 말고 실제 발언에서 자연스럽게 지어줘. 8개 안팎이면 좋아.
3. 각 그룹마다 표로 정리해줘: (a) 그룹 이름, (b) 몇 명이 언급했는지(P1,P3처럼 누구인지 표시), (c) 대표 발언 원문 2개를 누구 발언인지와 함께 그대로 인용, (d) 이 그룹이 말하는 핵심을 한 문장으로.
4. 여러 명이 공통으로 언급한 그룹을 위로 올려서 정렬해줘.
5. 마지막에, 표 전체를 근거로 '핵심 인사이트' 3~5개를 써줘. 인사이트는 단순 요약이 아니라 "왜 그런지 / 그래서 무엇을 시사하는지"까지 담아줘. 각 인사이트마다 근거가 된 그룹과 참여자를 괄호로 표시해줘.

규칙: 원문에 없는 말은 절대 지어내지 마. 한 명만 말한 소수 의견은 버리지 말고 '소수 의견' 그룹으로 따로 모아줘. 발언이 어느 그룹인지 애매하면 억지로 넣지 말고 '분류 애매'로 빼줘.

예시: 참가자가 6명이면 첫 줄의 P{n}.txt는 P6.txt로, {n}명은 6명으로 바꿉니다. (즉 "P1.txt ~ P6.txt 파일을 모두 읽어줘. … 심층 인터뷰 6명의 녹취록/요약이야.")

한 파일(research.txt)로 만든 경우: 위 블록 대신 아래 블록을 통째로 복사해 붙여넣으세요. (첫 줄만 다르고 나머지는 동일합니다 — 둘 중 자신에게 맞는 블록 하나만 고르면 됩니다.)

복사해서 쓰세요
이 폴더의 research.txt 파일을 읽어줘. [P1], [P2]처럼 참가자별로 구분되어 있어. {우리 앱 재구매 경험}에 대한 인터뷰/설문 응답이야.

어피니티 다이어그램 방식으로 종합해줘. 순서는 이렇게:

1. 먼저 참가자들의 발언에서 의미 있는 조각(한 문장 단위의 관찰·불편·바람)을 뽑아줘. 진행자 질문 말고 참여자 발언만.
2. 비슷한 조각끼리 묶어서 그룹을 만들어줘. 그룹 이름은 미리 정하지 말고 실제 발언에서 자연스럽게 지어줘. 8개 안팎이면 좋아.
3. 각 그룹마다 표로 정리해줘: (a) 그룹 이름, (b) 몇 명이 언급했는지(P1,P3처럼 누구인지 표시), (c) 대표 발언 원문 2개를 누구 발언인지와 함께 그대로 인용, (d) 이 그룹이 말하는 핵심을 한 문장으로.
4. 여러 명이 공통으로 언급한 그룹을 위로 올려서 정렬해줘.
5. 마지막에, 표 전체를 근거로 '핵심 인사이트' 3~5개를 써줘. 인사이트는 단순 요약이 아니라 "왜 그런지 / 그래서 무엇을 시사하는지"까지 담아줘. 각 인사이트마다 근거가 된 그룹과 참여자를 괄호로 표시해줘.

규칙: 원문에 없는 말은 절대 지어내지 마. 한 명만 말한 소수 의견은 버리지 말고 '소수 의견' 그룹으로 따로 모아줘. 발언이 어느 그룹인지 애매하면 억지로 넣지 말고 '분류 애매'로 빼줘.

결과 확인

이런 형태가 나오면 정상입니다: 언급자 많은 순으로 정렬된 그룹 표, 각 그룹 아래 원문 인용, 마지막에 핵심 인사이트 3~5개, '소수 의견'·'분류 애매' 그룹.

💡 이렇게 나오면 정상입니다: 그룹이 딱 8개가 아니라 6개, 10개로 나와도 괜찮습니다. 데이터 양·주제에 따라 달라집니다.

💡 함정: 참가자가 3명 이하로 적으면 그룹이 억지로 쪼개지거나 너무 뭉뚱그려질 수 있습니다. 결과가 어색하면 "그룹을 더 크게(적게) 묶어줘" 같은 후속 요청으로 조정하세요.

저장하기

결과를 확인했으면 아래처럼 이어서 입력해 파일로 저장합니다.

복사해서 쓰세요
지금까지 결과를 표와 인사이트 그대로 synthesis.md 파일로 저장해줘.

💡 이렇게 나오면 정상입니다: "synthesis.md 파일을 생성했습니다" 같은 메시지와 함께 폴더에 synthesis.md가 생깁니다. Finder/탐색기에서 파일이 실제로 생겼는지 확인하세요.

STEP 3. 사례 ② — 페르소나 2종 + 저니맵 생성 (실습 20~35분)

여기서부터가 오늘의 핵심입니다: 방금 만든 synthesis.md가 이 사례의 입력 데이터가 됩니다. 원문: persona-journey.md 2단계 프롬프트인데, 원래는 research.txt(원본 인터뷰 모음)를 입력으로 쓰지만, 오늘은 이미 한 번 종합된 synthesis.md를 입력으로 씁니다 — "한 사례의 출력이 다음 사례의 입력이 된다"는 감각이 여기서 생깁니다.

아래를 복사해 붙여넣고 { } 부분만 바꾸세요:

복사해서 쓰세요
synthesis.md 파일을 읽어줘. 이건 {우리 앱 재구매 경험}에 대한 인터뷰를 어피니티 방식으로 종합한 결과야.

이 데이터만 근거로 페르소나 초안 2종과 저니맵 1종을 만들어줘.

[페르소나 2종]
- 종합 결과에서 행동·니즈가 뚜렷하게 갈리는 두 무리를 찾아 각각 페르소나 1명으로 대표시켜줘. 유형을 미리 정하지 말고 실제 그룹·인용에서 자연스럽게 묶어줘.
- 각 페르소나마다: (a) 한 줄 별칭과 대표 인용문 1개(원문 그대로), (b) 기본 정보(나이대·직업·이용 빈도 — 데이터에 있는 것만, 없으면 '미확인'), (c) 목표 2~3개, (d) 핵심 페인포인트 2~3개, (e) 이 페르소나를 뒷받침하는 참가자 번호(P2, P5처럼).

[저니맵 1종]
- 두 페르소나 중 먼저 나온(첫 번째) 페르소나를 기준으로, 이 서비스를 쓰는 과정을 4~6단계로 나눠줘.
- 각 단계마다 표로: 단계명 | 사용자 행동 | 감정(한 단어+1점~5점) | 페인포인트 | 기회(개선 힌트).
- 감정 점수와 페인포인트는 반드시 데이터에 근거가 있을 때만 적고, 근거가 된 참가자 번호를 함께 표시해줘.

원문에 없는 정보는 절대 지어내지 마. 데이터로 뒷받침이 안 되는 칸은 '데이터 없음'이라고 솔직히 적어줘. 추측이 필요한 부분은 [추정]이라고 표시해줘.

결과 확인

이런 형태가 나오면 정상입니다: 페르소나 A/B 각각 별칭·인용문·기본정보표·목표·페인포인트(모두 근거 참가자 번호 포함), 그 아래 저니맵 표(단계별 감정 점수·페인포인트·기회).

💡 이렇게 나오면 정상입니다: 몇몇 칸에 데이터 없음이나 [추정]이 붙어 있습니다. 이건 오류가 아니라 "근거 없이 지어내지 마"라는 규칙이 제대로 작동한 증거입니다. 오히려 모든 칸이 빈틈없이 꽉 차 있다면 더 의심해야 합니다.

💡 함정: 페르소나 A와 B가 사실상 같은 사람처럼 보일 때가 있습니다(데이터가 적을 때 자주 발생). 이럴 땐 "두 페르소나가 실제로 뭐가 다른지 목표·페인포인트를 나란히 비교해서 보여줘"라고 되물어 확인하세요. 진짜 안 갈리면 그대로 인정하고 넘어가도 됩니다 — 억지로 다르게 만들라고 하면 안 됩니다.

💡 함정: 저니맵의 감정 점수(예: "짜증 2/5")는 AI가 임의로 매긴 숫자입니다. 어느 단계가 더 힘든지 순서 참고용일 뿐, 이 숫자를 그대로 지표·통계로 옮기지 마세요.

저장하기

복사해서 쓰세요
이 결과를 persona-journey.md 파일로 저장해줘. 그리고 페르소나마다 "우리가 아직 모르는 것(리서치 공백)" 항목을 한 줄씩 추가해줘 — 다음 인터뷰에서 물어볼 거리를 위한 거야.

STEP 4. 근거 대조 실습 — 스테레오타입 누출 잡기 (실습 35~45분)

persona-journey.md의 각 칸에는 (P3)처럼 근거 참가자 번호가 붙어 있습니다. 이 번호가 진짜로 그 참가자가 한 말인지 원본 파일(1단계에서 저장한 P1.txt… 또는 research.txt)에서 직접 검색해 확인하는 것이 이번 실습의 마지막 단계입니다.

  1. persona-journey.md를 열고 페르소나 A의 항목을 하나 고릅니다(예: 페인포인트 ①).
  2. 근거로 붙은 참가자 번호(예: P3)를 확인합니다.
  3. 원본 파일(P3.txt 또는 research.txt 안의 [P3] 구간)을 열어 Ctrl/Cmd+F로 관련 단어를 검색합니다.
  4. 실제로 그런 발언이 있는지, 뉘앙스가 왜곡되지 않았는지 확인합니다.
  5. 결과를 워크시트(worksheet.md)에 기입합니다. 최소 페르소나 1개, 항목 3개 이상을 대조하세요. - worksheet.md는 손으로 채우는 인쇄용 표입니다. 편한 방법을 고르세요: (a) 인쇄해서 손으로 체크·기입, (b) 표 내용을 통째로 복사해 Notion·Google Docs 등에 붙여넣고 화면에서 채우기. 메모장 같은 일반 텍스트 편집기에서 마크다운 표를 직접 고치는 것은 권장하지 않습니다(표가 쉽게 깨집니다).

💡 이렇게 나오면 정상입니다: 대부분 맞지만, 가끔 "AI가 살짝 매끄럽게 다듬었네" 싶은 경우가 나옵니다. 이건 흔한 일입니다. 원문과 뜻이 통하면 통과, 원문에 아예 없는 내용이 붙었으면 "스테레오타입 누출"로 워크시트에 표시하세요.

💡 함정: 근거 번호가 없거나 [추정]이라고 적힌 칸은 대조할 원문이 없다는 뜻입니다. 이런 칸은 "근거 없음 — 사람이 판단 필요"로 워크시트에 그대로 기록하면 됩니다. 억지로 원문을 끼워 맞추지 마세요.

이 프롬프트로 AI에게 재확인을 시켜도 좋습니다:

복사해서 쓰세요

공유·정리 (마지막 15분)

  • 완성한 synthesis.md, persona-journey.md, 워크시트를 옆 사람과 화면 공유로 보여주며 "어떤 인사이트가 나왔는지" 한 줄씩 나눕니다.
  • 오늘 만든 파일들은 각자 실무 폴더로 그대로 가져가 회의 자료로 쓸 수 있습니다(.md 파일은 내용을 복사해 Notion·Google Docs 등에 붙여넣으면 표가 정돈되어 보입니다).
  • 강사가 "AI 페르소나는 결론이 아니라 초안"이라는 점을 다시 짚습니다 — 팀 검토 전까지는 확정본으로 쓰지 않습니다.
  • 같은 데이터를 넣어도 다시 돌리면 페르소나 구성·표현이 조금씩 달라질 수 있습니다(비결정성). 오늘 나온 결과를 유일한 정답으로 여기지 말고, 중요한 결정을 앞두고 있다면 2~3번 다시 돌려 매번 공통으로 나오는 신호(반복 등장하는 페인포인트·무리)를 기준으로 삼으세요.

오늘의 성공 기준 체크리스트

  • [ ] 내 데이터로 만든 synthesis.md(어피니티 그룹 + 핵심 인사이트)가 폴더에 있다
  • [ ] synthesis.md를 입력으로 만든 persona-journey.md(페르소나 2종 + 저니맵)가 폴더에 있다
  • [ ] 페르소나 1개 이상의 근거 번호를 원문과 대조해 워크시트에 "맞음/틀림/근거없음"을 기록했다
