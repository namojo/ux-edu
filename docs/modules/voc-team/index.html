실습 가이드 — VoC 분석 팀을 만들어 내 리뷰 돌리기

L2⏱ 90분모듈 3 / 6
항목 내용
레벨 / 시간 L2 / 90분
선수 조건 L1 두 모듈(first-contact, first-harness) 수료 — Claude Code 실행 + revfactory/harness 설치 + 첫 하네스 구성 경험이 있어야 합니다
준비물 자기 서비스의 실제 리뷰/CS 티켓(익명화). 못 가져왔다면 강사가 배포하는 대체 데이터를 씁니다 — 다만 그 경우 오늘 만든 결과가 실무로 바로 이어지지는 않습니다
주교재 voc-mining.md (오늘 실습은 이 사례의 2단계 팀 구성 프롬프트의 골격을 그대로 쓰고, 여러분 데이터에 맞는 슬롯만 채워 넣습니다)

오늘 만드는 것

자기 VoC 데이터를 다루는 분석 팀을 직접 구성·실행해서, 주제별 분류 · 대표 원문 인용 · 건수가 담긴 "개선 기회 리포트" 초안을 받습니다. 그리고 팀의 검증 담당이 표시한 인용문을 사람이 원문과 직접 대조하는 것까지 해서 improvement.md 파일로 저장합니다.

분석 팀이란? 하네스(revfactory/harness)로 만든, 여러 역할을 가진 AI 에이전트 모음입니다. 오늘 팀에는 리뷰를 모으는 역할, 주제를 분류하는 역할, 인용문을 검증하는 역할, 리포트를 쓰는 역할이 따로따로 있습니다. 이미 first-harness 모듈에서 이 구조를 한 번 만들어 보셨습니다 — 오늘은 그걸 자기 데이터로 다시 해 봅니다.

시간 배분

구간 시간 내용
도입·시연 25분 voc-mining.md 팀 미리보기 + 2단계 구성 프롬프트 해설 (강사)
실습 50분 자기 데이터로 구성 → 실행 → 검증
공유·정리 15분 결과 공유 + 막힌 지점 나누기

0단계: 시작 전 확인

  • [ ] Claude Code가 켜져 있고, first-contact에서 만든 작업 폴더(또는 새 폴더)로 이동했다
  • [ ] revfactory/harness 플러그인이 설치되어 있다 (first-contact에서 설치 완료했다면 별도 작업 불필요)
  • [ ] 지참한 리뷰/CS 티켓 파일이 준비되어 있다 (엑셀·구글시트·메모장 어디든 괜찮습니다)

💡 설치가 안 되어 있다면: 대화창에 아래 두 줄을 차례로 입력하세요. (first-contact에서 이미 했다면 건너뜁니다) /plugin marketplace add revfactory/harness /plugin install harness@harness-marketplace

1단계: 내 VoC 데이터를 reviews.txt로 정리하기 (약 10분)

  1. 작업 폴더를 하나 엽니다. 예: voc-실습
  2. 폴더 안에 리뷰/티켓 내용을 텍스트 파일로 넣습니다. 파일 이름은 reviews.txt로 통일하는 것을 권장합니다. - 엑셀·구글시트에 리뷰가 있다면: 해당 열(리뷰 내용 열, 가능하면 별점 열 포함)을 통째로 드래그해 복사(Cmd/Ctrl+C) → 메모장(또는 텍스트 편집기)에 붙여넣기(Cmd/Ctrl+V) → reviews.txt로 저장 - 이미 CSV 파일이 있다면 그대로 폴더에 넣어도 됩니다 (tickets_cs.csv처럼 원래 이름 유지 가능) - 여러 채널(앱스토어 리뷰 + CS 티켓 + 설문)이 있다면 파일을 채널별로 나눠 넣어도 괜찮습니다 — 다음 단계 프롬프트에서 팀에게 "여러 파일"이라고 알려주면 됩니다

💡 이렇게 나오면 정상입니다 — 별점(평점) 열이 없는 경우 리뷰에 별점이 없고 텍스트만 있어도 괜찮습니다. 이 경우 팀은 감정(긍정/부정)을 글 내용만으로 판정하게 됩니다. 다음 단계 구성 프롬프트에 별점 열이 없다는 것을 한 줄 덧붙이세요 — 예: "별점 데이터는 없어서 텍스트 내용으로만 감정을 판정해줘." 이렇게 알려주지 않으면 팀이 있지도 않은 별점 열을 찾다가 혼란스러운 결과를 낼 수 있습니다. 반대로 별점 열이 있다면 "별점도 함께 참고해서 감정을 판정해줘"라고 적어 주세요.

💡 비교할 전 분기 리포트가 있다면 지난 분기에 정리해 둔 리포트 파일(.md나 .txt)이 있다면 같은 폴더에 넣어 두세요. 팀이 "이번엔 무엇이 늘고 줄었는지" 비교해 줍니다. 없다면 걱정하지 마세요 — 오늘 만드는 리포트가 다음 분기 비교의 첫 기준선이 됩니다. 구성 프롬프트에서 비교 관련 문장은 그냥 빼면 됩니다.

2단계: VoC 분석 팀 구성하기 (약 10분)

아래 프롬프트를 복사해 대화창에 붙여넣습니다. { } 중괄호 부분만 여러분 상황에 맞게 바꾸세요 (중괄호 기호 자체는 지워야 합니다). (2)번 줄의 별점 문장은 /로 나뉜 두 갈래 중 자기 상황에 맞는 것 하나만 남기고, 화살표(→)와 나머지 문장은 통째로 지우세요.

복사해서 쓰세요
하네스 구성해줘: {여러분 서비스명}의 {앱 리뷰·CS 티켓·설문 응답 등 — 내가 준비한 데이터 종류}를 분석하는 VoC 분석 팀이 필요해.
{reviews.txt 등 준비한 파일명}을 입력하면,
(1) 하나로 모아 정제하고
(2) 주제별로 분류하고 감정(긍정/부정)을 판정하고
   {별점 있으면 → 별점도 함께 참고해서 감정을 판정해줘 / 별점 없으면 → 별점 데이터는 없어서 텍스트 내용으로만 감정을 판정해줘}
(3) 리포트에 넣을 인용문이 원문에 실제로 있는지 검증하고 개인정보를 가리고
(4) {전 분기 리포트가 있다면: 전 분기 리포트와 비교해서 어떤 주제가 늘고 줄었는지 표로 정리하는}
팀으로 만들어줘. 최종 결과는 대표 인용과 건수가 포함된 주제별 개선 기회 표로, 마크다운 리포트로 저장해줘.

이 프롬프트는 voc-mining.md의 2단계 구성 프롬프트의 골격은 그대로 두고, 여러분 데이터에 맞는 슬롯(서비스명·별점 유무·전 분기 비교 유무)만 추가로 채워 넣은 것입니다. 문장 구조를 새로 만들 필요는 없습니다 — 워크시트 4번·6번에 미리 적어둔 문장을 그대로 옮기면 됩니다.

Enter를 누르면 화면에 "생성 중..." 비슷한 표시가 뜨고 잠시 기다리게 됩니다.

💡 이렇게 나오면 정상입니다 — 생성 대기 팀을 만드는 데 보통 몇 분 정도 걸립니다. 화면이 멈춘 것처럼 보여도 안에서는 여러 파일을 만드는 중입니다. 중간에 권한을 묻는 확인 창이 뜨면 "예/허용" 계열을 선택해 진행하세요(파일을 만들어도 되는지 묻는 정상적인 절차입니다).

💡 이렇게 나오면 정상입니다 — 매번 팀 구성이 조금씩 다름 같은 프롬프트를 넣어도 팀원 이름이나 역할 구분이 세션마다 조금씩 다르게 나올 수 있습니다(예: classifier가 topic-tagger로 나올 수도 있음). 역할 4가지(수집·분류·검증·리포트)가 다 들어 있는지, 그중 검증 담당이 반드시 있는지만 확인하면 됩니다.

생성이 끝나면 .claude/agents/ 폴더를 열어 팀원 파일이 만들어졌는지 확인하세요. first-harness에서 본 것처럼 수집·분류·검증·리포트 역할이 있어야 합니다. 하네스가 마지막에 알려주는 실행 트리거 문구를 기억해 두세요(다음 단계에서 씁니다).

💡 .claude 폴더가 안 보인다면 .claude처럼 점(.)으로 시작하는 폴더는 맥 Finder·윈도우 탐색기에서 기본적으로 숨겨져 있습니다. 맥에서는 Finder 창에서 Cmd+Shift+.(마침표)를 누르면 숨김 폴더가 나타납니다. 폴더를 직접 찾기 번거롭다면 대화창에 "방금 만든 팀원 목록 보여줘"라고 입력해서 대화로 확인해도 됩니다.

3단계: 팀 실행하고 개선 기회 표 받기 (약 15분)

새 세션에서 실행하는 것을 권장합니다(대화창에 /clear 입력, 또는 claude 재실행). 하네스가 알려준 트리거 문구를 입력합니다. 예:

복사해서 쓰세요
VoC 분석 실행해줘. reviews.txt 파일로 분석해줘.

실행이 끝나면 주제별 개선 기회 표(주제 · 건수 · 대표 인용 · 감정 등)를 받습니다.

이어서 관심 가는 주제 1개를 골라 후속 프롬프트로 더 파 봅니다. 예:

복사해서 쓰세요
방금 표에서 가장 건수가 많은 주제 하나를 더 세부 유형으로 나눠서 보여줘.

이렇게 "표를 다시 보여줘 / 이 주제만 더 파줘" 식으로 대화를 이어가는 감각은 first-contact에서 이미 연습했습니다 — 같은 방식입니다.

4단계: 검증 — 인용 원문 대조 (약 15분)

팀의 검증 담당(verifier)이 "원문 대조 완료" 같은 검증 표시(문구는 팀마다 조금 다를 수 있습니다)를 붙인 대표 인용문이 리포트에 있을 것입니다. 표시가 안 보이면 대화창에 "검증한 대표 인용 몇 개만 보여줘"라고 물어보세요. 이걸 사람이 직접 확인하는 단계입니다.

  1. 리포트에서 대표 인용문 1건 이상을 고릅니다.
  2. 원본 reviews.txt(또는 원본 엑셀/CSV) 파일을 열고, 인용된 문장의 일부를 Cmd+F(Mac) 또는 Ctrl+F(Windows)로 검색합니다.
  3. 원문에 정확히 그 문장이 있는지 확인합니다.
  4. 동시에 그 인용문에 이름·전화번호·이메일 같은 개인정보가 남아있지 않은지도 확인합니다.

아래 표에 확인 결과를 적어 두세요 (그대로 improvement.md에 옮겨 붙이면 됩니다):

확인한 인용문 원문에 있음? (O/X) 개인정보 잔존? (있음/없음) 비고

💡 이렇게 나오면 정상입니다 — 원문에 없는 표현이 섞여 있을 때 검증 담당이 "대조 완료"로 표시했어도, 여러 문장을 매끄럽게 합치면서 원문에 없는 표현이 살짝 섞이는 경우가 있습니다(환각). 이럴 땐 리포트의 그 인용문을 원문 그대로 다시 써 달라고 요청하면 됩니다 — 예: "이 인용문은 원문과 달라. reviews.txt에서 정확히 그대로 다시 찾아줘."

  1. 최종 리포트(개선 기회 표 + 검증 결과)를 작업 폴더에 improvement.md 파일로 저장해 달라고 팀에게 요청합니다:
복사해서 쓰세요
지금까지의 개선 기회 표와 방금 검증한 인용문 대조 결과를 합쳐서 improvement.md 파일로 저장해줘.

5단계 (선택 — 시간이 남으면): 하네스 회고 맛보기 — 팀 다듬기 (약 5~10분)

1~4단계까지가 실습 50분의 필수 범위입니다. 여기까지 마쳤다면 오늘의 성공 기준은 이미 달성한 것입니다. 5단계는 시간이 남을 때, 또는 공유·정리 시간에 이어서 해 보는 보너스 실습입니다. 시간이 부족하면 수업 후 혼자 해 봐도 됩니다.

결과에서 아쉬운 부분 하나를 골라 팀에게 말로 피드백합니다. 코드를 고치는 게 아니라 대화로 팀을 개선하는 것입니다. voc-mining.md 4단계 예시를 참고해 아래처럼 입력해 보세요(자기 상황에 맞게 바꿔도 됩니다):

복사해서 쓰세요
하네스 회고: 주제 분류가 너무 뭉뚱그려져 있어. 가장 건수가 많은 주제를 세부 유형 2~3개로 더 잘게 나누도록 분류 담당을 개선해줘.
복사해서 쓰세요
하네스 회고: 요약이 너무 길어. 리포트 맨 위에 "이번 리뷰에서 가장 시급한 개선 포인트 3줄"을 먼저 넣도록 리포트 담당을 개선해줘.

피드백 후 팀을 다시 실행해(3단계 트리거 문구 재입력) 리포트 형식이 실제로 바뀌었는지 확인합니다.

구축은 1회, 실행은 매번입니다. 오늘 만든 이 VoC 분석 팀은 다음번에 새 리뷰 파일만 갈아 끼우고 3단계 트리거만 다시 입력하면 재사용할 수 있습니다.

마무리 체크리스트 (성공 기준)

  • [ ] 자기 VoC 데이터로 분석 팀을 구성했다 (.claude/agents/에 수집·분류·검증·리포트 역할 확인)
  • [ ] 팀을 실행해 주제별 개선 기회 표(대표 인용·건수 포함)를 받았다
  • [ ] 인용문 1건 이상을 원문과 직접 대조해 검증했다
  • [ ] 결과를 improvement.md 파일로 저장했다
  • [ ] (선택, 5단계·시간이 남았다면) 하네스 회고로 피드백 1회를 넣어 팀이 바뀌는 것을 확인했다

오늘 만든 VoC 분석 팀과 improvement.md가 여러분이 가져가는 실물 산출물입니다. 다음 모듈(research-persona-team)에서는 이번에 만든 것과 비슷한 방식으로, 두 개의 팀을 연결해 리서치 데이터에서 페르소나까지 만들어 봅니다.
