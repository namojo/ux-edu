오늘 만드는 것 내 서비스 VoC의 주제별 개선 기회 표 (improvement.md)

이 가이드는 강사 없이 혼자 따라 해도 처음부터 끝까지 완주할 수 있도록 화면에 보이는 순서 그대로 적었습니다. 막히면 각 단계의 💡 박스부터 확인하세요.

시작 전 확인

  • [ ] Claude Code가 설치되어 있고, first-contact/prompt-and-verify 모듈에서 켜 본 적이 있다
  • [ ] 내 서비스의 실제 리뷰/CS 티켓(익명화) 을 가져왔다
  • 못 가져왔다면 강사가 배포하는 대체 샘플을 대신 씁니다. 단, 그 경우 오늘 결과물은 "연습용"이 되고 실무로 바로 못 씁니다 — 다음 기회에 자기 데이터로 꼭 한 번 더 돌려 보세요.
  • [ ] 데이터에 고객 이름·전화번호·주문번호가 보이면 지금 미리 지우거나 가릴 준비가 되어 있다 (010-****-**** 식으로)

오늘의 흐름 (90분)

복사해서 쓰세요
[도입·시연 25분]  강사가 usecases/voc-mining.md 절차를 자기 데이터로 먼저 시연
        ↓
[실습 50분]  1단계 reviews.txt 준비 → 2단계 분류 프롬프트 실행
             → 3단계 관심 주제 파고들기 → 4단계 저장+검증
        ↓
[공유·정리 15분]  옆 사람과 표 1개씩 보여주며 "이게 우리 팀에 왜 유용한지" 한마디

1단계: reviews.txt 준비하기

목표: 내 리뷰/CS 티켓을 Claude Code가 읽을 수 있는 텍스트 파일 하나로 모은다.

  1. 바탕화면이나 문서 폴더에 작업용 폴더를 만듭니다. 예: voc-2026-2분기
  2. 가져온 리뷰/티켓을 그 폴더 안에 reviews.txt라는 이름으로 저장합니다. - 엑셀에 있다면: 리뷰 내용 열을 통째로 선택 → 복사 → 메모장(Windows)/텍스트편집기(Mac)에 붙여넣기 → reviews.txt로 저장 - 리뷰 하나가 한 줄 또는 한 문단으로 구분되어 있으면 좋습니다 (엑셀에서 복사하면 보통 자동으로 그렇게 됩니다)
  3. 별점 열이 있는지 확인하세요. 있다면 리뷰 내용 열과 함께 그대로 복사해 붙여넣습니다. 별점·날짜·기기 정보는 있으면 지우지 말고 같이 두세요.

💡 별점 열이 없다면? 그대로 진행해도 됩니다. 다만 이후 2단계 프롬프트의 "4번(부정 리뷰 분석)" 항목은 결과에서 자동으로 빠집니다(Claude가 "별점 정보가 없어 건너뛴다"고 알려줍니다). 별점을 나중에 구할 수 있으면 다음에 다시 돌려서 비교해 보세요. 지금은 주제별 분류(1~3번)만으로도 충분히 유용한 결과가 나옵니다.

  1. 터미널을 열고 reviews.txt가 든 폴더로 이동한 뒤 claude를 입력해 Claude Code를 켭니다. - Mac: 폴더를 Finder에서 우클릭 → "폴더에서 새로운 터미널 열기" (이 메뉴가 안 보이면 기본적으로 꺼져 있는 상태입니다 — 시스템 설정 › 키보드 › 단축키 › 서비스에서 켤 수 있습니다. 바로 켜기 번거로우면 아래 cd 명령 방법을 쓰세요) - Windows: 폴더를 파일 탐색기에서 열고 위쪽 주소창에 cmd 입력 후 Enter - 명령어로 이동: cd Desktop/voc-2026-2분기 (본인이 폴더를 만든 위치에 맞춰 경로 수정)

💡 ls로 확인: 잘 들어왔는지 모르겠으면 ls(폴더 안 파일 목록 보기)를 입력해 reviews.txt가 보이는지 확인하세요. 안 보이면 cd 경로가 틀린 것이니 폴더 위치를 다시 확인합니다.

💡 개인정보가 보이면 지금 처리하세요: 붙여넣기 전에 이름·전화번호·주문번호를 지우거나 가리는 게 원칙입니다. 이미 붙여넣었다면 지금 파일을 다시 열어 확인·수정하세요. 이유는 4단계에서 다시 다룹니다.

2단계: 분류 프롬프트 실행하기

목표: voc-mining.md의 2단계 프롬프트를 내 서비스에 맞게 바꿔 실행해 주제별 표를 받는다.

아래를 그대로 복사해 붙여넣고, { } 중괄호 부분만 내 서비스로 바꾸세요. 그 외 문장은 손대지 마세요 — 검증 규칙("지어내지 마", "애매하면 따로 빼줘")이 포함되어 있어 결과 품질을 좌우합니다.

복사해서 쓰세요
reviews.txt 파일을 읽어줘. 이건 {우리 쇼핑 앱}의 {2026년 2분기} 사용자 리뷰/CS 티켓 모음이야.

다음을 해줘:
1. 리뷰들을 내용 주제별로 분류해줘. 주제는 미리 정하지 말고 실제 내용에서 자연스럽게 묶어서 5~8개 정도로 만들어줘.
2. 각 주제마다: (a) 주제 이름, (b) 해당 리뷰 대략 몇 건인지(전체 대비 비율도), (c) 대표 리뷰 원문 2개를 그대로 인용, (d) 사용자가 겪는 핵심 불편 한 문장 요약.
3. 표로 정리하고, 건수가 많은 주제부터 위로 정렬해줘.
4. (파일에 별점이 함께 있을 때만) 별점이 낮은(부정적인) 리뷰에서 특히 두드러지는 주제 3개를 따로 짚어줘. 별점 정보가 파일에 없으면 이 항목은 건너뛰고, 별점이 없다고 알려줘 — 별점을 임의로 추측하지는 마.

원문에 없는 내용은 절대 지어내지 말고, 판단이 애매한 리뷰는 '분류 애매'로 따로 빼줘.

바꿀 부분: - {우리 쇼핑 앱} → 내 서비스/제품 이름 - {2026년 2분기} → 이 데이터가 수집된 기간

💡 권한 확인 창이 뜨면? Claude Code가 reviews.txt를 읽어도 되는지 물어보는 창이 뜰 수 있습니다. first-contact에서 본 것과 같은 화면입니다 — "허용(Allow)"을 선택하면 진행됩니다. 이유 없이 계속 막힌다면 지금 폴더 안에 reviews.txt가 실제로 있는지(ls) 다시 확인하세요.

💡 결과가 화면 중간에 멈춘 것처럼 보이면? 리뷰가 많으면(수백 건) 분류에 시간이 걸립니다. 화면 아래 커서가 깜빡이고 있다면 아직 작업 중인 것이니 기다리세요. 1~2분 이상 아무 변화가 없다면 그때 강사/TA에게 알려주세요. 리뷰가 아주 많으면(수천 건) Claude가 파일 앞부분만 읽고 일부만 분석했는데도 결과가 정상처럼 보일 수 있습니다. 결과를 받으면 전체 몇 건 중 몇 건을 분석한 거야?라고 물어 reviews.txt의 전체 건수와 맞는지 확인하세요. 안 맞으면 파일을 여러 개로 나눠 나눠서 돌리는 게 안전합니다.

💡 표가 너무 길어서 결과가 잘려 보이면? 터미널 창을 위로 스크롤하면 앞부분을 다시 볼 수 있습니다. 또는 방금 결과를 improvement.md 파일로 저장해줘라고 먼저 요청하면(4단계 참고) 파일로 열어 전체를 편하게 볼 수 있습니다.

결과는 이런 표 형태로 나옵니다(예시, 실제 수치는 다릅니다):

순위 주제 건수(비율) 핵심 불편 요약
1 결제/쿠폰 오류 82건 (27%) 쿠폰 적용 후 결제 단계에서 금액이 원래대로 돌아옴
2 배송 지연·추적 61건 (20%) 발송 알림은 왔는데 며칠째 배송 상태가 안 바뀜

표 아래에는 주제별 대표 리뷰 원문 2개가 그대로 인용되어 딸려 나옵니다. 별점 열이 있었다면 표 아래에 "부정 리뷰에서 두드러진 주제" 목록도 함께 나옵니다.

💡 '분류 애매' 묶음도 같이 나옵니다 프롬프트 마지막 줄이 판단하기 애매한 리뷰를 '분류 애매'로 따로 빼도록 지시해 뒀습니다. 이 묶음은 표와 별도로 결과 맨 아래쯤에 나옵니다. 건수가 적어 보여도 지나치지 말고, 4단계에서 안전·보안 관련 내용이 섞여 있는지 한 번 훑어보세요.

3단계: 관심 주제 하나 더 파기

목표: 표에서 가장 눈에 띄는 주제 1개를 골라 세부 유형으로 더 쪼갠다.

표를 보고 우리 팀이 가장 궁금한 주제 1개를 정한 뒤, 아래처럼 이어서 입력합니다 (숫자·주제명은 내 표에 맞게 바꾸세요):

복사해서 쓰세요
1번 '결제/쿠폰 오류' 주제만 더 파줘. 이 안에서도 세부 유형으로 다시 3~4개로 나누고, 각 유형별 대표 리뷰를 붙여줘.

💡 이전 대화를 기억하고 있는지 궁금하다면: 그대로 이어서 입력하면 됩니다. Claude Code는 같은 창에서는 방금 만든 표 내용을 기억하고 있어서 "1번 주제"라고만 말해도 알아듣습니다. 새 터미널을 열었다면 기억하지 못하니 처음부터 다시 시작해야 합니다.

4단계: 저장하고 검증하기

목표: 결과를 파일로 남기고, 결과 안의 인용 1건 이상이 진짜 원문인지 확인한다.

  1. 아래처럼 입력해 파일로 저장합니다:
복사해서 쓰세요
이 결과를 표 그대로 improvement.md 파일로 저장해줘. 그리고 각 주제마다 "예상 개선 방향" 열을 하나 더 추가해줘 — 단, 이건 제안이라는 걸 표시해줘.

  1. 폴더 안에 improvement.md가 생겼는지 ls로 확인하고 열어 봅니다.

  2. 인용 검증(필수): 표 안에 나온 대표 리뷰 원문 중 1건을 골라, reviews.txt를 열고 찾기 기능(Mac Cmd+F / Windows Ctrl+F)으로 그 문장이 글자 그대로 있는지 검색합니다. - 있다 → 검증 통과. 이 방식으로 신뢰하고 써도 됩니다. - 없다/살짝 다르다 → Claude Code에게 원문 그대로만 인용해줘, 방금 인용은 원문에 없어라고 다시 요청해 고칩니다. 이게 바로 prompt-and-verify 모듈에서 배운 환각 검증입니다.

  3. 개인정보 잔존 확인: improvement.md에 인용된 원문에 고객 이름·전화번호·주문번호가 딸려 나왔는지 훑어봅니다. 남아 있으면 공유 전에 가립니다.

  4. 소수 의견 확인(필수): 표는 건수가 많은 순으로 정렬돼 있어 건수 1~2건짜리 이슈는 눈에 잘 안 띕니다. 하지만 그 소수 주제나 '분류 애매' 묶음 안에 안전·보안·환불처럼 심각한 불만이 섞여 있을 수 있습니다. 표 하단의 소수 주제와 '분류 애매' 목록을 한 번 훑어보고, 눈에 띄는 게 있으면 워크시트에 적어 두세요. 이 표를 "개선 기회 전체"로 팀에 보고할 때, 이 확인 없이는 건수가 적지만 심각한 이슈를 놓칠 수 있습니다.

💡 improvement.md를 어떻게 열어보나요? 메모장/텍스트편집기로 열면 #, | 같은 기호가 그대로 보입니다(마크다운 형식이라 그렇습니다, 표·제목을 기호로 표현한 텍스트 파일이라는 뜻). 기호가 신경 쓰이면 VS Code 같은 편집기나, 마크다운을 표로 보여주는 뷰어로 열어도 됩니다. 오늘은 내용 확인이 목적이니 메모장으로 열어도 충분합니다.

💡 숫자(건수·비율)를 그대로 믿어도 되나요? 순위(무엇이 더 큰 문제인지)는 신뢰해도 되지만, "27%" 같은 숫자를 정확한 통계로 보고서·KPI에 그대로 옮기지 마세요. AI가 애매한 리뷰를 분류하며 경계에서 오차가 생길 수 있습니다.

공유·정리 (15분)

옆 사람/조와 improvement.md를 화면으로 보여주며 아래를 30초씩 공유합니다.

  • 가장 건수가 많았던 주제는 무엇이었나
  • 검증한 인용 1건은 원문과 맞았나, 틀렸나
  • 이 표를 이번 주 어디에 쓸 것 같은가 (회의 자료? 백로그 우선순위?)

오늘의 성공 기준 체크

  • [ ] 내 VoC 데이터로 주제별 개선 기회 표(대표 인용·건수 포함)를 만들었다
  • [ ] 그 표를 improvement.md 파일로 저장했다
  • [ ] 인용 1건을 reviews.txt 원본과 대조해 검증했다 (맞음/틀림 판정 완료)
  • [ ] 소수 주제·'분류 애매' 묶음을 훑어 심각한 이슈가 묻히지 않았는지 확인했다

네 개 모두 체크됐다면 오늘 목표를 달성한 것입니다. improvement.md는 다음 분기에도 같은 방식으로 비교할 수 있으니 잘 보관해 두세요.

다음 걸음(참고): 이 작업이 매 분기 반복된다면 voc-mining.md의 "한 걸음 더"에 나온 것처럼 수집→분류→검증→리포트를 역할이 나뉜 에이전트 팀(하네스)으로 만들 수 있습니다. 이 내용은 3회차 my-harness 모듈에서 다룹니다.
