페르소나 팀을 만들어 '근거 없는 페르소나'를 자동으로 걸러내기

따라 하기근거 검증 담당을 둔 팀으로 페르소나·저니맵을 만들 때
항목 내용
영역 페르소나 & 저니맵
난이도 중급
소요 시간 구축 약 20분 + 실행 회당 약 15~20분
준비물 인터뷰 요약·설문 응답을 모은 텍스트 파일 1개, revfactory/harness 설치(아래 0단계)
팀 패턴 Pipeline + Producer-Reviewer — 정리→생성→검증→저니맵으로 순서대로 흐르되(Pipeline), 페르소나 '작성 담당'이 만든 초안을 '검증 담당'이 근거 대조해 반려까지 하는 생성-검증 구조(Producer-Reviewer)가 핵심

이런 상황에서 쓰세요

인터뷰 8건을 마치고 설문까지 돌렸는데, 이걸 페르소나와 저니맵으로 옮기는 단계에서 매 라운드 막힙니다. 노트를 다시 훑고, 공통점을 포스트잇으로 묶고, "이 사람은 몇 살로 할까" 고민하다 보면 하루가 갑니다. 게다가 급하면 실제 데이터가 아니라 머릿속 인상으로 페르소나를 지어내게 되고, 저니맵의 감정 곡선도 근거 없이 "여기서 답답함" 식으로 대충 찍게 됩니다. 이게 분기마다, 리서치 라운드마다 똑같은 형식으로 반복된다면 — 그때가 매번 프롬프트를 붙여넣는 대신 작은 AI 팀(하네스) 을 한 번 만들어 두고 실행만 반복할 시점입니다. 특히 "근거 번호가 원문에 진짜 있나"를 한 칸씩 대조하는, 사람이 제일 지겨워하지만 꼭 해야 하는 검증을 전담 팀원이 매번 빠짐없이 해줍니다.

팀 미리보기

하네스가 만들어 줄 팀은 이렇습니다:

팀원 역할
리서치 정리 담당 인터뷰·설문 원본을 참가자별 표준 형식([P1] 구분, 기본 정보 정렬)으로 다듬고, 실명·연락처·회사명을 익명 표기로 바꿈
페르소나 작성 담당 (Producer) 정리된 데이터에서 행동·니즈가 갈리는 무리를 찾아 페르소나 2종을 만들고, 모든 칸에 근거 참가자 번호(P3처럼)를 부착
근거 검증 담당 (Reviewer) 작성 담당이 붙인 근거 번호가 원문에 실제로 있는지 한 칸씩 대조. 근거 없는 칸은 데이터 없음/[추정]으로 강제 표시하고, 근거가 부실한 페르소나는 작성 담당에게 반려하며, 익명화가 안 된 채 남은 개인정보도 함께 지적. 반려·수정·표시한 내역은 「검증 로그」로 남김
저니맵 작성 담당 검증을 통과한 첫 번째 페르소나 기준으로 4~6단계 저니맵을 만들고, 감정·페인포인트 칸에도 근거 번호를 붙임

여기서 핵심은 작성 담당(Producer)과 검증 담당(Reviewer)이 분리돼 있다는 점입니다. 혼자서 "만들고 스스로 검토"하면 자기가 상상으로 채운 칸을 스스로 통과시키기 쉽지만, 검증 담당은 오직 원문 대조만 하므로 근거 없는 페르소나가 그냥 통과되지 않습니다.

따라 하기

0단계: 하네스 설치 (처음 한 번만)

Claude Code(폴더 안의 파일을 읽고 쓸 수 있는 AI 도구) 대화창에 아래 두 줄을 차례로 입력합니다. 플러그인(Claude Code에 기능을 추가하는 확장)으로 하네스를 설치하는 명령입니다. 이미 설치했다면 이 단계는 건너뜁니다.

아직 Claude Code를 켜지 않았다면 먼저 1단계의 3~5번(터미널 열기 → 폴더 이동 → claude 실행) 을 해서 대화창을 연 뒤, 이 두 줄을 입력하세요. (설치가 끝나면 다시 1단계 준비로 돌아옵니다.)

복사해서 쓰세요
/plugin marketplace add revfactory/harness
/plugin install harness@harness-marketplace

1단계: 준비

먼저 리서치 데이터를 하나의 텍스트 파일로 모읍니다.

  1. 바탕화면이나 문서 폴더에 작업용 폴더를 하나 만듭니다. 예: persona-2026-앱개편
  2. 인터뷰 요약과 설문 응답을 그 폴더 안에 research.txt(메모장/텍스트편집기로 만든 파일)로 저장합니다. 형식은 자유지만, 아래처럼 구분돼 있으면 AI가 더 잘 읽습니다. - 인터뷰는 참가자별로 [P1], [P2]처럼 구분선을 넣어 주세요. 나이·직업·이용 빈도 같은 기본 정보가 있으면 맨 앞에 적어 둡니다. - 설문은 엑셀에서 응답 열을 통째로 복사해 붙여넣으면 됩니다. 주관식 답변이 특히 유용합니다.
  3. 터미널(명령어를 입력하는 창)을 엽니다. Mac은 Spotlight(Cmd+Space)에서 터미널을 검색해 엽니다. Windows는 시작 메뉴에서 PowerShell을 검색해 엽니다.
  4. 방금 연 창에서 1번 폴더로 이동합니다. 창에 cd 를 치고 한 칸 띄운 뒤, 1번 폴더를 마우스로 창 안에 끌어다 놓으면 경로가 자동 입력됩니다. 그대로 Enter. (예: cd /Users/내이름/Desktop/persona-2026-앱개편)
  5. 이어서 claude 를 입력하고 Enter를 눌러 Claude Code를 켭니다. 처음 켜면 로그인 안내나 폴더 접근 허용을 묻는 창이 뜰 수 있는데, 안내대로 진행/허용하면 됩니다.

개인정보 주의: 원본에 실명·연락처·회사명이 있어도, 정리 담당 팀원이 익명 처리를 하도록 팀을 구성합니다. 다만 팀에만 의존하지 말고, 특히 민감한 정보(주민번호·계좌 등)는 붙여넣기 전에 직접 지우는 것이 안전합니다.

2단계: 팀 구성 (바이브코딩: 코드를 직접 쓰지 않고 말로 팀을 설계하는 방식)

아래를 복사해 붙여넣고, {중괄호} 부분만 바꾸세요:

복사해서 쓰세요
하네스 구성해줘: 사용자 리서치 데이터에서 페르소나와 저니맵 초안을 만드는 페르소나 팀이 필요해.
인터뷰 요약과 설문 응답을 모은 텍스트 파일(research.txt)을 입력하면 아래 순서로 일하는 팀으로 짜줘.

① 리서치 정리 담당: 원본을 참가자별 표준 형식([P1] 구분, 기본 정보 정렬)으로 다듬고, 실명·연락처·회사명을 익명 표기로 바꾼다.
② 페르소나 작성 담당: 행동·니즈가 뚜렷이 갈리는 무리를 찾아 페르소나 2종을 만든다. 유형을 미리 정하지 말고 실제 응답에서 자연스럽게 묶는다. 각 페르소나의 모든 항목(별칭·대표 인용문·기본 정보·목표·페인포인트)에 근거 참가자 번호(P3처럼)를 반드시 붙인다.
③ 근거 검증 담당: 작성 담당이 붙인 근거 번호가 research.txt 원문에 실제로 있는지 한 칸씩 대조한다. 근거가 없는 칸은 '데이터 없음' 또는 [추정]으로 강제 표시하고, 원문에 없는 특성을 상식으로 채운 페르소나는 작성 담당에게 반려해 다시 만들게 한다. 개인정보가 남아 있으면 함께 지적한다.
④ 저니맵 작성 담당: 검증을 통과한 첫 번째 페르소나 기준으로 이 앱 사용 과정을 4~6단계로 나눈다. 단계별 표(단계|사용자 행동|감정(한 단어+1~5점)|페인포인트|기회)로 만들고, 감정 점수와 페인포인트에도 근거 참가자 번호를 붙인다.

근거 없는 페르소나는 반드시 걸러지는 생성-검증(Producer-Reviewer) 구조로 짜줘.
원문에 없는 정보는 절대 지어내지 않는 것이 이 팀의 최우선 규칙이야.
검증 담당이 반려·수정하거나 [추정]/'데이터 없음'으로 표시한 내역과 남은 개인정보 지적을,
리포트 끝에 「검증 로그」 섹션으로 반드시 함께 남겨줘 — 사람이 무엇이 걸러졌는지 확인할 흔적이야.
결과는 마크다운(제목·표를 쓸 수 있는 텍스트 문서 형식, 확장자 .md) 리포트 파일(persona-journey.md)로 저장해줘.

잠시 후 .claude/agents/ 폴더에 팀원 파일들이(예: organizer.md, persona-writer.md, evidence-reviewer.md, journey-writer.md), .claude/skills/에 팀의 작업 방법(예: persona-journey/SKILL.md)과 팀을 실행하는 오케스트레이터(팀 전체의 실행을 지휘하는 스킬)가 생깁니다. 하네스가 마지막에 "이런 팀을 만들었어요" 요약을 보여주니, 팀 미리보기 표와 비슷한 구성이 나왔는지 그 요약으로 확인하면 됩니다.

3단계: 팀 실행

새로 시작할 때는 대화창에 오케스트레이터 트리거 문구(하네스가 구성 끝에 알려줍니다. 보통 아래와 같은 형태)를 입력하면 팀이 일을 시작합니다:

복사해서 쓰세요
research.txt로 페르소나 만들어줘. 이건 우리 가계부 앱 사용자 데이터야.

이런 식의 결과가 나옵니다(내용은 예시입니다):

페르소나 A — "쫓기는 사회초년생 지현"

"돈이 어디로 새는지 모르겠어요. 월급날 되면 이미 통장이 비어 있어요." (P3, 원문 인용)

항목 내용
기본 정보 20대 후반 / 직장 2년차 / 앱 이용 주 1회 미만 (근거 P3, P7)
목표 ① 이번 달 지출이 예산을 넘었는지 빠르게 확인(P3) ② 고정지출을 한눈에 파악(P7)
페인포인트 ① 카드 여러 개를 일일이 입력하기 귀찮음(P3, P7) ② 알림이 너무 많아 무시하게 됨(P7)

페르소나 B — "꼼꼼한 외벌이 가장 민수" (별칭·표 동일 형식으로 이어짐)

저니맵 — 지현 기준

단계 사용자 행동 감정 페인포인트 기회
1. 가입/연동 카드사 연동 시도 기대 4/5 연동할 카드가 많아 중간에 포기(P3) 주거래 카드 1개만 먼저 연동하는 간편 경로
2. 첫 지출 확인 이번 주 지출 조회 혼란 2/5 카테고리 자동 분류가 실제와 다름(P3, P7) 분류 수정을 한 번에 학습시키는 UI
3. 예산 초과 알림 푸시 알림 받음 짜증 2/5 알림이 잦아 꺼버림(P7) 주간 1회 요약 알림으로 빈도 조절

이 팀만의 특징은 마지막에 검증 담당의 검증 로그가 함께 나온다는 점입니다. 근거 없는 칸이 실제로 걸러진 흔적이 남습니다:

복사해서 쓰세요
[검증 로그]
- 페르소나 A '목표 ③ SNS로 가계부 공유' → research.txt에 근거 없음. 삭제하고 반려함.
- 페르소나 B '기본 정보: 40대' → P5는 "40대"라 했으나 P2는 미확인.
  '40대(P5) / 일부 미확인'으로 수정.
- 저니맵 4단계 '만족 5/5' → 근거 참가자 없음. '[추정]'으로 표시.
- 개인정보: P4 응답에 실명 1건 잔존 → '[P4]'로 익명화 완료.

이 로그가 사람 검토의 출발점입니다. 반려·수정된 항목만 먼저 확인하면 되니, 초안 전체를 처음부터 의심할 필요가 없습니다.

4단계: 팀 다듬기 (진화)

결과가 아쉬운 부분은 팀에게 말로 피드백합니다:

  • 하네스 회고: 검증 담당이 근거 1건짜리 칸도 통과시키네. 근거가 1명뿐인 페인포인트는 "근거 1건, 일반화 주의"라고 꼬리표를 달도록 검증 담당을 개선해줘.
  • 하네스 회고: 페르소나마다 "우리가 아직 모르는 것(리서치 공백)" 항목을 한 줄씩 넣어줘 — 다음 인터뷰에서 물어볼 거리를 위한 거야. 작성 담당 규칙에 추가해줘.

다음 실행부터 반영됩니다. 구축은 1회, 실행은 매번 — 다음 라운드에는 research.txt만 새 파일로 바꿔 넣고 3단계 문구만 다시 입력하면, 같은 형식·같은 검증 수준의 초안이 나옵니다.

꼭 사람이 확인하세요

  • 검증 담당이 있어도 최종 대조는 사람 몫입니다. 검증 담당은 근거 없는 칸을 대부분 걸러내지만, 그 자신도 AI라 원문 대조를 놓칠 수 있습니다. 초안 페르소나·저니맵에서 (검증 로그에 안 걸린 채) 통과된 핵심 페인포인트 2~3개를 골라, (P3) 번호를 research.txt에서 직접 검색해 정말 그 참가자가 그렇게 말했는지 대조하세요.
  • 감정 점수는 눈금이 아니라 힌트입니다. "짜증 2/5"의 숫자는 AI가 임의로 매긴 것입니다. 단계 간 힘든 순서는 참고하되, 숫자 자체를 지표로 옮기지 마세요.
  • 페르소나 2명이 진짜 다른 무리인지 보세요. 데이터가 적으면 팀이 억지로 둘로 쪼개, 사실상 같은 사람을 이름만 바꿔 낼 수 있습니다. 두 페르소나의 목표·페인포인트가 실제로 갈리는지, 뒷받침 참가자가 겹치지 않는지 확인하세요.
  • 소수의 강한 신호가 평균에 묻히지 않게 보세요. 8명 중 1명만 말한 심각한 불편(예: 접근성 문제)은 "대표적이지 않다"며 페르소나에서 빠질 수 있습니다. 검증 로그에 안 담긴 소수 의견도 한 번 훑고, 중요하면 별도로 기록하세요.
  • 같은 데이터라도 다시 돌리면 결과가 달라질 수 있습니다. AI는 같은 research.txt를 넣어도 실행할 때마다 페르소나 구성·표현이 조금씩 바뀝니다. 중요한 결정 앞에서는 2~3번 다시 돌려 매번 공통으로 나오는 신호(반복 등장하는 무리·페인포인트)를 기준으로 삼으세요.
  • 이건 '초안'이지 '결론'이 아닙니다. AI 페르소나는 실제 리서치를 대체하는 게 아니라 1차 정리를 도와주는 도구입니다. 산출물 어딘가에 "AI 초안, 사람 검토 필요"와 사용한 데이터 범위를 적어 두면 나중에 오해를 막습니다.

하네스가 과한 경우

이번 리서치가 1회성이거나(다음 분기 반복 계획 없음), 인터뷰가 3~4건뿐이라면 팀을 만드는 20분이 아깝습니다. 그럴 땐 Claude Code 대화창에 프롬프트 한 번이면 충분합니다:

복사해서 쓰세요
research.txt를 읽고, 이 데이터만 근거로 페르소나 2종과 저니맵 1종을 만들어줘.
모든 항목에 근거 참가자 번호(P3처럼)를 붙이고, 원문에 없는 정보는 지어내지 말고
근거 없는 칸은 '데이터 없음'이나 [추정]으로 표시해줘.

판단 기준은 딱 하나입니다: 같은 형식의 페르소나·저니맵이 라운드마다 반복해서 필요한가? 그렇다면 팀을, 아니라면 프롬프트 한 줄을 쓰세요. 반복될수록 "근거 대조 검증을 매번 빠짐없이 해준다"는 팀의 이점이 커집니다.

한 걸음 더

  • 앞단 팀과 연결하기. 인터뷰 녹취 정리부터 자동화하고 싶다면, 리서치 종합 팀(research-synthesis 사례)이 만든 인사이트 리포트를 이 페르소나 팀의 입력으로 넘기는 파이프라인으로 이을 수 있습니다. 하네스 회고: 리서치 종합 팀의 출력 파일을 이 페르소나 팀이 바로 입력으로 받도록 연결해줘 처럼 요청하면 됩니다.
  • 팀원 추가. 페르소나별 광고/서비스 시나리오를 함께 뽑고 싶다면 "시나리오 작성 담당"을 한 명 더 붙일 수 있습니다: 하네스 회고: 검증 통과한 페르소나마다 대표 사용 시나리오 1개를 쓰는 팀원을 추가해줘.
  • 미리 만들어진 하네스 둘러보기. 처음부터 만들지 않고 가까운 것을 설치해 고치는 출발점으로 revfactory/harness-100(10개 도메인 100개 팀 하네스)을 참고하세요.

참고한 업계 동향

  • AI로 페르소나·저니맵 초안을 만드는 흐름은 이미 업계 표준 도구(UXPressia 등)와 실무자 워크플로우로 자리잡고 있습니다. (UX Collective — Kyle Soucy, UXPressia AI Mapping)
  • 동시에 학계·실무 양쪽에서 위험이 반복 지적됩니다: AI 페르소나는 스테레오타입 누출(근거 없이 "20대라서 SNS를 즐겨 함" 식으로 채우는 것), 근거 없는 제약 상상(환각), 모델 버전에 따른 결과 변동, 실제 사용자와의 불일치를 보입니다. 결론은 "AI 페르소나는 실제 리서치를 보완할 뿐 대체하지 않으며, 사용한 데이터 출처와 검토 이력을 함께 밝혀야 한다" 입니다. 이 사례가 작성 담당과 검증 담당을 분리(Producer-Reviewer) 하고 근거 번호·[추정] 표시를 강제하는 이유가 바로 여기에 있습니다. (CHI 2026 — Responsible Use of AI Personas, IxDF — AI vs Researched Personas, arXiv 스코핑 리뷰(81편))

참고: 위 출처는 이 사례집의 기존 검증 자료에서 이어받았으며, 이번 작성 중 새 웹 조사는 수행하지 않았습니다.
