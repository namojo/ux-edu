사용성 테스트 세션 노트에서 이슈 목록 + 심각도 우선순위 뽑기

따라 하기세션 노트에서 이슈 목록과 심각도 우선순위를 만들 때
항목 내용
영역 사용성 테스트 분석
난이도 중급
소요 시간 약 30~45분
준비물 참가자별 테스트 세션 노트 + 태스크 성공/실패 기록을 모은 텍스트 파일 1개, Claude Code가 설치된 컴퓨터

이런 상황에서 쓰세요

사용성 테스트를 5~8명 돌리고 나면 참가자별 관찰 노트가 수십 장 쌓입니다. "3번 참가자는 결제 버튼을 못 찾아 헤맸고, 5번은 쿠폰 입력창을 배송지로 착각했고…" 머릿속엔 다 있는데, 이걸 이슈 목록으로 정리하고 "무엇부터 고쳐야 하는지" 심각도를 매겨 팀에 공유하려면 하루가 통째로 날아갑니다. 게다가 여러 참가자에게서 같은 문제가 반복됐다는 사실(= 심각도의 핵심 근거)을 노트를 오가며 눈으로 맞춰봐야 합니다. 이 1차 정리를 AI에게 맡기고, 사람은 심각도 판정과 맥락 해석에만 집중하는 방법입니다.

따라 하기

1단계: 준비

먼저 세션 기록을 하나의 텍스트 파일로 모읍니다.

  1. 바탕화면이나 문서 폴더에 작업용 폴더를 하나 만듭니다. 예: usability-2026-07
  2. 참가자별 노트를 그 폴더 안에 sessions.txt(메모장/텍스트편집기로 만든 파일)로 저장합니다. 형식은 자유지만, 참가자를 구분할 수 있게 표시해 두면 좋습니다. 예: ``` [P1 / 40대 / 첫 구매] 태스크1(상품검색) 성공 / 45초 태스크2(장바구니 담기) 성공 / 20초 태스크3(쿠폰 적용 후 결제) 실패 — 쿠폰 입력창을 배송 메모칸으로 착각, 결국 쿠폰 없이 결제 관찰: "할인칸이 어디 있지?"라고 세 번 중얼거림. 결제 버튼이 스크롤 아래 있어 못 봄.

[P2 / 30대 / 재구매] 태스크3 성공 / 90초(오래 걸림) 관찰: 쿠폰은 찾았으나 적용 후 금액이 안 바뀌어 두 번 재시도 `` - **태스크 성공/실패와 소요 시간을 같이 적어두는 게 이 사례의 핵심 재료입니다.** AI가 "몇 명 중 몇 명이 실패했는지"로 심각도를 뒷받침해 줍니다. 3. 터미널(명령어를 입력하는 검은 창)을 열고, **방금 만든 폴더로 이동**한 뒤claude를 입력해 Claude Code를 켭니다. Claude Code는 그 폴더 안의 파일을 읽고 쓸 수 있는 AI 도구입니다. - **폴더로 이동하는 법 (Mac)**: 터미널에cd를 치고 한 칸 띄운 다음, 방금 만든 폴더를 마우스로 터미널 창에 **끌어다 놓으면**(드래그&드롭) 폴더 경로가 자동으로 입력됩니다. 그 상태로 Enter를 누르면 이동 완료. (cd는 "이 폴더로 들어가라"는 명령입니다.) - **폴더로 이동하는 법 (Windows)**: 탐색기에서 만든 폴더를 연 뒤, 맨 위 **주소창을 클릭해cmd를 입력하고 Enter** 하면 그 폴더 위치에서 터미널이 바로 열립니다. (이 방법은 터미널 열기와 폴더 이동이 한 번에 됩니다. 바로claude` 를 입력하면 됩니다.) - 터미널을 여는 법 자체가 처음이라면 온보딩 문서의 "터미널 여는 법"을 먼저 참고하세요.

개인정보 주의: 노트에 참가자 실명·연락처가 있다면 P1, P2 같은 익명 코드로 바꾼 뒤 저장하세요. 이유는 아래 "꼭 사람이 확인하세요"에서 다시 짚습니다.

2단계: 프롬프트 입력

아래를 복사해 붙여넣고, {중괄호} 부분만 바꾸세요:

복사해서 쓰세요
sessions.txt 파일을 읽어줘. 이건 {우리 쇼핑 앱}의 {결제 플로우} 사용성 테스트 세션 노트야.
참가자는 P1부터 P{8}까지이며, 각자 태스크 성공/실패와 관찰 코멘트가 적혀 있어. (P1~P 뒤의 숫자를 노트에 있는 마지막 참가자 번호로 맞춰 적어줘. 총 인원은 파일에 있는 참가자 수를 그대로 세어줘.)

다음을 해줘:

1. 노트 전체에서 사용성 이슈를 뽑아 목록으로 만들어줘. 같은 문제가 여러 참가자에게서 나타나면 하나의 이슈로 합치고, 몇 명(누구)에게서 관찰됐는지 적어줘.

2. 각 이슈마다 Nielsen 심각도 척도(0~4)로 등급을 매겨줘. 등급 기준은 다음과 같아:
   - 4 = 사용성 재앙: 반드시 출시 전 수정. 다수가 태스크 자체를 완수 못 함
   - 3 = 심각: 우선 수정. 여러 명이 크게 헤매거나 실패
   - 2 = 경미: 우선순위 낮게 수정. 불편하지만 완수는 함
   - 1 = 사소(미관 수준): 시간 남으면 수정
   - 0 = 사용성 문제 아님
   등급을 정한 근거(몇 명에게서, 실패였는지 지연이었는지)를 반드시 한 줄로 함께 써줘.

3. 아래 표로 정리하고, 심각도가 높은 순 → 같으면 관찰된 참가자 수가 많은 순으로 정렬해줘.
   열: 이슈 | 관찰된 참가자(수) | 관련 태스크 | 심각도(0~4) | 심각도 근거 | 대표 관찰 인용

4. 표 아래에 태스크별 성공률(성공 인원 / 전체 인원)을 정리해줘.

노트에 없는 내용은 절대 지어내지 마. 관찰이 한 명에게서만 나온 이슈는 심각도를 신중하게 매기고 '단일 관찰'이라고 표시해줘. 판단이 애매한 건 '판정 보류'로 따로 빼줘.

3단계: 결과 확인

이런 식의 결과가 나옵니다(내용은 예시입니다):

이슈 관찰된 참가자(수) 관련 태스크 심각도 심각도 근거 대표 관찰 인용
쿠폰 입력창을 배송 메모칸으로 착각 P1, P4, P6 (3명) 태스크3 결제 4 3명이 쿠폰 적용 자체를 완수 못 하고 정가로 결제 "할인칸이 어디 있지?" (P1)
결제 버튼이 스크롤 아래 숨어 안 보임 P1, P3, P5 (3명) 태스크3 결제 3 3명이 결제 단계에서 30초 이상 버튼을 못 찾음 "다 됐는데 어디서 사죠?" (P5)
쿠폰 적용 후 금액이 즉시 안 바뀜 P2 (1명, 단일 관찰) 태스크3 결제 2 1명이 반복 시도했으나 결국 완수 "눌렀는데 그대로네" (P2)

태스크별 성공률 - 태스크1(상품검색): 8/8 성공 (100%) - 태스크2(장바구니 담기): 7/8 성공 (88%) - 태스크3(쿠폰 적용 후 결제): 3/8 성공 (38%) ← 결제 플로우에 문제 집중

판정 보류: P7의 "글씨가 작다" 코멘트 — 심각도 판단에 노트 정보가 부족해 보류

4단계: 다듬기

첫 결과가 나오면 후속 프롬프트로 원하는 각도로 좁혀 갑니다. 아래처럼 이어서 입력하면 됩니다:

  • 심각도 4와 3짜리 이슈만 따로 뽑아서, 각 이슈에 "재현 조건(어떤 화면/어떤 행동에서 발생하는지)"과 "관련 참가자의 관찰 코멘트 전부"를 붙여줘. 개발·디자인 팀에 전달할 버그 리포트 형식으로.
  • 이 표를 findings.md 파일로 저장해줘. 그리고 각 이슈마다 "개선 방향(제안)" 열을 하나 더 추가하되, 이건 AI 제안이라는 걸 열 제목에 명시해줘.

두 번째처럼 파일로 저장(findings.md는 마크다운, 즉 표·제목을 기호로 표현한 텍스트 파일)해 두면 회의 자료로 바로 공유하거나 다음 라운드 테스트와 비교할 수 있습니다.

꼭 사람이 확인하세요

  • 심각도 등급은 AI 제안일 뿐, 최종 판정은 사람이 합니다. Nielsen 척도는 원래 "빈도 × 영향 × 지속성"을 종합해 전문가가 매기는 값입니다. AI는 노트에 적힌 표면 정보(실패했는지, 몇 명인지)로만 추정하므로, 비즈니스 임팩트가 큰 이슈(예: 결제 이탈)를 과소평가할 수 있습니다. AI 등급을 초안으로 받고, 팀이 조정하세요.
  • "관찰된 참가자 수"가 진짜인지 대조하세요. AI가 서로 다른 참가자의 비슷한 코멘트를 하나로 뭉치거나, 반대로 같은 문제를 다른 이슈로 쪼갤 수 있습니다. 심각도 4·3 이슈는 원문 노트에서 실제로 그 참가자들이 그 문제를 겪었는지 눈으로 확인하세요.
  • 인용이 진짜 원문인지 검증하세요. AI는 관찰 코멘트를 그럴듯하게 다듬거나 합칠 수 있습니다(환각). 대표 인용 몇 개는 sessions.txt에서 실제로 검색해 그대로 있는지 확인하세요. 다르면 "관찰 노트 원문 그대로만 인용해"라고 다시 지시합니다.
  • 성공률 숫자는 노트 기록에 의존합니다. 노트에 성공/실패가 명확히 안 적힌 태스크는 AI가 추측했을 수 있습니다. 성공률이 의사결정에 쓰인다면 원 기록과 맞춰보세요.
  • 단일 관찰(한 명)이라고 무시하지 마세요. 참가자 1명에게서만 나왔지만 치명적인 문제(결제 오류, 개인정보 노출 등)가 있을 수 있습니다. '단일 관찰'과 '판정 보류' 항목도 사람이 한 번 훑고 심각도를 직접 판단하세요.
  • 뉘앙스·감정은 AI가 놓칩니다. "성공은 했지만 표정이 굳었다", "짜증 섞인 한숨" 같은 정성적 신호는 노트에 적혀 있어도 AI가 심각도에 잘 반영하지 못합니다. 관찰자가 느낀 정성적 마찰은 사람이 보강하세요.
  • 개인정보가 남아 있지 않은지 최종 확인하세요. 1단계에서 예고한 대로, 참가자 실명·연락처·이메일 같은 개인정보는 AI에 파일을 넣기 전과 리포트를 팀에 공유하기 전 두 번 모두 확인합니다. 노트를 급히 모으다 보면 일부 참가자만 실명이 남는 경우가 흔합니다. P1, P2 같은 익명 코드로 통일됐는지, 대표 인용문 안에 이름이 섞여 있지 않은지 눈으로 훑으세요.

한 걸음 더

이 분석이 테스트 라운드마다 반복된다면(예: 스프린트마다 사용성 테스트를 돌린다면), 매번 프롬프트를 붙여넣는 대신 에이전트 팀(하네스) 으로 승격할 가치가 있습니다. 하네스는 역할이 나뉜 AI들이 순서대로 일하는 작은 팀입니다. 예를 들어:

  • 정리 담당: 참가자별 노트를 표준 형식(참가자 코드·태스크·성공여부·관찰)으로 재구성
  • 이슈 추출 담당: 위 2단계 프롬프트를 고정 규칙으로 실행해 이슈 목록 + 심각도 초안 표 생성
  • 검증 담당: 인용문이 원문에 실제로 있는지, 관찰된 참가자 수가 맞는지 대조하고 개인정보가 남았는지 점검
  • 리포트 담당: 지난 라운드 결과와 비교해 "지난번에 고쳤는데 또 나온 이슈", "새로 생긴 이슈"를 강조한 요약본 작성

이렇게 만들어 두면 다음 라운드에는 노트 파일만 넣고 실행하면 같은 형식·같은 심각도 기준의 리포트가 나옵니다. "매 라운드 같은 기준으로, 같은 형식의 이슈 리포트가 필요하다"가 반복될 때가 하네스로 만들 시점입니다.

참고: Nielsen 심각도 척도(0=문제 아님, 1=미관 수준, 2=경미, 3=심각, 4=재앙)는 Nielsen Norman Group의 표준 척도를 따랐습니다(근거). 이 척도는 원래 여러 평가자가 독립적으로 매긴 값을 평균 내도록 설계됐으므로, AI 단독 판정을 최종값으로 쓰지 말고 사람 평가와 함께 쓰는 것이 원 취지에 맞습니다.

외부 동향 미확인: AI를 사용성 테스트 분석에 접목하는 2025~2026년 구체적 업계 사례는 웹 조사에서 충분히 확인되지 않았습니다. 프롬프트·산출물 예시는 실무 지식과 표준 심각도 척도에 기반한 재현 가능한 형태이나, 최신 전용 도구(테스트 녹화 자동 분석 등) 현황은 별도 확인이 필요합니다.
