경쟁 서비스 3종 온보딩 플로우를 비교표 한 장으로 만들기

따라 하기경쟁 서비스 온보딩을 비교표 한 장으로 정리할 때
항목 내용
영역 경쟁사 UX 벤치마킹
난이도 중급
소요 시간 약 40~60분 (화면 캡처·메모 정리 포함)
준비물 경쟁 서비스 3종의 온보딩 화면을 순서대로 캡처한 이미지, 각 화면을 말로 풀어쓴 메모 텍스트 파일 1개, Claude Code가 설치된 컴퓨터

이런 상황에서 쓰세요

"우리 가입 절차가 경쟁사보다 긴가요?"라는 질문이 회의에서 나올 때마다, 경쟁 앱 3개를 직접 깔아 가입해 보고 스크린샷을 찍은 뒤 파워포인트에 나란히 붙여 표를 만들곤 합니다. 화면은 다 모았는데, 막상 "몇 단계인지, 어디서 이탈이 날 것 같은지, 우리가 배울 점은 뭔지"를 표로 정리하려면 반나절이 훌쩍 갑니다. 게다가 3개를 같은 기준으로 비교했는지도 자신이 없습니다. 이 작업에서 화면을 모으고 관찰 메모를 남기는 것은 사람이, 같은 기준으로 정렬해 비교표로 엮는 것은 AI가 맡는 방법입니다.

업계에서도 2026년 기준 SaaS 팀들이 경쟁사 온보딩 플로우 벤치마킹에 AI를 적극 쓰고 있습니다. AI로 여러 화면·리뷰를 공통 주제로 묶어 비교하되 "잘못 해석하지 않도록 사람이 반드시 검증한다"가 공통 원칙입니다(출처는 문서 하단).

따라 하기

1단계: 준비

핵심은 AI에게 넘기기 전에, 각 화면을 사람이 직접 보고 말로 풀어 적는 것입니다. AI는 여러분의 메모를 표로 정렬하는 데는 뛰어나지만, 화면을 여러분만큼 정확히 "보지는" 못합니다. 그래서 관찰은 사람이 합니다.

  1. 바탕화면이나 문서 폴더에 작업용 폴더를 하나 만듭니다. 예: onboarding-bench-2026
  2. 경쟁 서비스 3종의 온보딩(첫 실행 ~ 가입 완료)을 직접 진행하며 화면을 순서대로 캡처합니다. 파일 이름을 순서대로 붙이면 나중에 편합니다. 예: A_01_시작.png, A_02_이메일입력.png …
  3. 같은 폴더 안에 notes.txt(그냥 메모장/텍스트편집기로 만든 파일)를 만들고, 화면마다 관찰한 것을 한 줄씩 적습니다. 정해진 형식은 없지만, 아래처럼 서비스·순서·화면에서 본 것을 적으면 AI가 정확히 정렬합니다.

``` [서비스 A] 1. 시작 화면 — "3초면 시작" 문구 + 큰 버튼 하나. 회원가입/로그인 선택 없음. 2. 이메일 입력 — 이메일만 요구. 비밀번호는 다음 단계로 분리. 3. 소셜 로그인 — 카카오/애플/구글 3개. 이메일보다 위에 배치. 4. 관심사 선택 — 6개 카드 중 3개 이상 선택 강제. 스킵 버튼 없음. 5. 완료 — 바로 홈. 튜토리얼 오버레이 4장 순차 노출.

[서비스 B] (아래는 앞 3화면만 발췌 — 실제로는 마지막 화면까지 모두 적으세요) 1. 시작 화면 — 로그인/회원가입 탭 분리. 가입 버튼이 작음. 2. 정보 입력 — 이메일+전화+이름을 한 화면에서 모두 요구. 3. 전화 인증 — 문자 인증번호 입력. 건너뛰기 없음.

[서비스 C] (앞 3화면만 발췌) 1. 시작 화면 — 가입 없이 "둘러보기" 버튼이 가장 큼. 2. 홈 체험 — 로그인 전에 핵심 기능을 바로 써봄. 3. 가입 유도 — 저장하려 할 때 카카오/애플 로그인만 요청. ```

  • 세 서비스 모두 위와 같은 형식으로, 화면마다 한 줄씩 적으세요. 한 서비스만 자세히 적고 나머지를 대충 적으면 비교표가 한쪽으로 치우칩니다. (위 예시는 지면상 A만 전체, B·C는 앞부분만 보여 준 것입니다.)
  • 화면 개수가 서비스마다 달라도 괜찮습니다. 그대로 적으면 AI가 "A는 5단계, B는 7단계"처럼 비교해 줍니다.
  • "스킵 버튼 없음", "필수 입력이 몇 개" 같은 판단이 필요한 관찰을 넣을수록 표가 풍부해집니다.
  1. 터미널(명령어를 입력하는 검은 창)을 1단계에서 만든 폴더 안에서 연 뒤 claude 를 입력해 Claude Code를 켭니다. Claude Code는 자신이 켜진 폴더 안의 파일(메모와 이미지)을 읽는 AI 도구라, 반드시 onboarding-bench-2026 폴더 안에서 켜야 notes.txt와 이미지를 읽을 수 있습니다. 폴더 안에서 터미널을 여는 가장 쉬운 방법은 이렇습니다: - (Mac) 방법 1: Finder에서 onboarding-bench-2026 폴더를 우클릭 → "폴더에서 새로운 터미널 열기". (이 메뉴가 안 보이면 방법 2를 쓰세요.) - (Mac) 방법 2: 터미널을 먼저 켠 뒤 cd 를 입력하고(cd 뒤에 한 칸 띄웁니다. cd는 "지정한 폴더로 이동" 명령입니다), 폴더를 터미널 창으로 드래그하면 경로가 자동으로 채워집니다. Enter를 누르면 이동 완료. - (Windows): 파일 탐색기로 폴더를 연 뒤, 위쪽 주소창을 클릭해 cmd 를 입력하고 Enter. 그 폴더 위치에서 터미널이 열립니다. - 어느 방법이든 터미널이 그 폴더에서 열렸으면, 이제 claude 를 입력합니다.

스크린샷을 굳이 안 넣고 메모만으로도 이 사례는 됩니다. 다만 이미지를 함께 넣으면 AI가 메모에서 빠뜨린 요소(버튼 색, 진행 표시줄 유무 등)를 보완해 줄 수 있습니다. 이미지를 참조시킬 때는 프롬프트에 파일 이름을 그대로 적으면 됩니다.

2단계: 프롬프트 입력

아래를 복사해 붙여넣고, {중괄호} 부분만 바꾸세요. 중괄호 안의 A=, B=, C=는 그대로 두고 뒤의 설명만 실제 서비스명으로 교체합니다. 예: {A=우리 유사 경쟁사} → {A=토스}, {B=시장 1위} → {B=카카오뱅크}, {C=신생 스타트업} → {C=(교체할 실제 신생 서비스명)}처럼 A·B·C 세 개 모두 바꾸세요. 이때 A·B·C 라벨은 notes.txt에 적은 [서비스 A]·[서비스 B]·[서비스 C]와 같은 순서로 맞추세요.

복사해서 쓰세요
notes.txt 파일을 읽어줘. 이건 경쟁 서비스 3종({A=우리 유사 경쟁사}, {B=시장 1위}, {C=신생 스타트업})의
온보딩(첫 실행부터 가입 완료까지) 플로우를 내가 직접 진행하며 화면별로 남긴 관찰 메모야.

다음을 해줘:
1. 세 서비스를 같은 기준으로 나란히 비교하는 표를 만들어줘. 행(비교 항목)은 다음을 포함해:
   - 총 단계 수(화면 개수)
   - 가입에 요구하는 필수 정보(이메일/전화/이름 등)
   - 소셜 로그인 제공 여부와 종류
   - 건너뛰기(스킵) 가능한 단계 여부
   - 첫 가치 경험까지 걸리는 체감 단계(=사용자가 "쓸모"를 처음 느끼는 지점)
   - 온보딩 완료 후 첫 화면(홈 직행/튜토리얼 등)
2. 표 아래에 "관찰된 강점"과 "관찰된 약점"을 서비스별로 각 2~3개씩 정리해줘.
3. 마지막에 "우리 서비스가 참고할 점" 3가지를 제안해줘. 단, 이건 제안이라는 걸 표시해줘.

중요: notes.txt에 적힌 내용만 근거로 써줘. 메모에 없는 화면이나 기능은 절대 지어내지 마.
메모만으로 판단이 안 되는 항목은 빈칸으로 두고 "메모 부족"이라고 표시해줘.

스크린샷도 함께 보게 하려면 마지막에 한 줄 덧붙이세요: A_로 시작하는 이미지 파일들도 함께 봐줘. 메모와 다르거나 메모에서 빠진 화면 요소가 있으면 표에 반영하고, 어디를 이미지로 보완했는지 표시해줘.

3단계: 결과 확인

이런 식의 결과가 나옵니다(내용은 예시입니다):

비교 항목 서비스 A 서비스 B 서비스 C
총 단계 수 5단계 7단계 3단계
필수 정보 이메일만 이메일+전화+이름 없음(둘러보기 먼저)
소셜 로그인 카카오/애플/구글 구글만 카카오/애플
스킵 가능 단계 없음(관심사 선택 강제) 프로필 사진 단계만 스킵 대부분 스킵 가능
첫 가치 경험까지 5단계 이후(가입 후) 7단계 이후 1단계(가입 전 체험)
완료 후 첫 화면 홈+튜토리얼 4장 홈 직행 둘러보기 화면

관찰된 강점 / 약점 (일부) - 서비스 C 강점: 가입 없이 먼저 써보게 해 진입 장벽이 가장 낮음. 필수 입력 0개. - 서비스 B 약점: 전화번호 인증까지 7단계 — 관찰 메모상 가장 길고, 이탈 위험 구간으로 보임. - 서비스 A 약점: 관심사 3개 선택을 강제(스킵 없음)해 흐름이 끊길 소지.

우리 서비스가 참고할 점 (제안) 1. C처럼 "가입 전 둘러보기"를 넣어 첫 가치 경험을 가입 앞으로 당기는 안 검토 2. B의 전화번호 필수 요구는 반면교사 — 우리 필수 정보를 최소화할 여지 점검 3. A의 튜토리얼 4장은 완료 후에도 이탈을 부를 수 있어, 스킵 버튼 제공 여부 확인

4단계: 다듬기

첫 표가 나오면 후속 프롬프트로 원하는 각도로 좁혀 갑니다. 아래처럼 이어서 입력하면 됩니다:

  • 총 단계 수 말고 "필수 입력 개수" 기준으로 세 서비스를 다시 정렬해줘. 가장 가벼운 순서로.
  • 이 표를 그대로 bench.md 파일로 저장해줘. 그리고 맨 위에 "3줄 요약"을 붙여줘 — 경영진 보고용으로.

두 번째처럼 파일로 저장(bench.md는 마크다운, 즉 표·제목을 기호로 표현한 텍스트 파일)해 두면 회의 자료로 바로 공유하거나, 다음 분기에 경쟁사가 온보딩을 바꿨을 때 비교 기준으로 재사용할 수 있습니다.

꼭 사람이 확인하세요

  • 표의 "사실" 칸(단계 수, 필수 정보 등)이 메모와 일치하는지 대조하세요. AI는 3종을 나란히 맞추는 과정에서 빈칸을 그럴듯하게 메우려는 경향이 있습니다(환각). 특히 "메모 부족"으로 비워야 할 칸에 추측이 들어갔는지, notes.txt와 한 줄씩 맞춰 보세요.
  • "첫 가치 경험까지", "이탈 위험" 같은 판단 칸은 AI의 해석일 뿐입니다. 이건 여러분의 관찰 메모를 재료로 AI가 추론한 것이라, 실제 사용자 데이터(이탈률)가 아닙니다. 근거로 삼되 결론으로 확정하지 마세요.
  • 관찰 자체의 편향을 경계하세요. AI 표는 여러분이 메모에 적은 것까지만 정확합니다. 세 서비스를 다른 컨디션(다른 기기, 다른 날, 서둘러 본 것)에서 봤다면 비교가 불공정해집니다. 가능하면 같은 조건에서 같은 깊이로 관찰한 메모를 넣으세요.
  • "참고할 점" 제안은 아이디어일 뿐입니다. 경쟁사가 그렇게 한 데는 우리가 모르는 사정(규제, 타깃 차이)이 있을 수 있습니다. 벤치마킹 결과를 그대로 우리 설계로 복사하지 말고, 우리 맥락에 맞는지 판단을 거치세요.
  • 최신성을 확인하세요. 경쟁사 온보딩은 수시로 바뀝니다. 캡처한 날짜를 메모와 표에 남겨, "언제 기준 비교인지"를 항상 함께 공유하세요.

한 걸음 더

경쟁사 벤치마킹이 분기마다, 또는 여러 경쟁사·여러 플로우(온보딩뿐 아니라 결제·해지까지)로 반복된다면, 매번 프롬프트를 붙여넣는 대신 에이전트 팀(하네스) 으로 승격할 가치가 있습니다. 하네스는 역할이 나뉜 AI들이 순서대로 일하는 작은 팀입니다. 예를 들어:

  • 관찰 정리 담당: 사람이 남긴 화면 메모와 스크린샷을 표준 형식(서비스·단계·관찰)으로 정돈
  • 비교 담당: 위 2단계 프롬프트를 고정된 비교 항목으로 실행해 3종 비교표 생성
  • 검증 담당: 표의 사실 칸이 메모와 일치하는지, 빈칸에 추측이 들어갔는지 대조
  • 추이 담당: 지난 분기 표와 비교해 "경쟁사가 이번에 바꾼 부분"만 하이라이트한 변화 리포트 작성

이렇게 만들어 두면 다음 분기에는 새 스크린샷과 메모만 넣고 실행하면 같은 기준의 비교표가 나오고, 무엇보다 "경쟁사가 무엇을 바꿨는지"를 자동으로 짚어 줍니다. "같은 항목으로, 주기적으로, 여러 대상을 비교한다"가 반복될 때가 하네스로 만들 시점입니다.
