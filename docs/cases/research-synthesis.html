인터뷰 분석 팀을 만들어 분기 리서치 종합 자동화하기

따라 하기분기마다 인터뷰 녹취 더미를 인사이트로 종합할 때
항목 내용
영역 사용자 리서치 종합 (research-synthesis)
난이도 중급 (구성 → 실행 → 피드백 루프까지)
소요 시간 구축 약 20~30분(처음 한 번) + 실행 회당 약 10~15분
준비물 인터뷰 녹취 텍스트 파일 여러 개, revfactory/harness 설치(아래 0단계)
팀 패턴 Pipeline(순차) — 수집 → 그룹핑 → 검증 → 리포트가 한 줄로 이어지는 구조. 중간에 검증 담당이 끼어 인용 오류를 걸러냅니다

이런 상황에서 쓰세요

분기마다 사용자 인터뷰를 8~12건 돌리고, 그 녹취록을 앞에 쌓아놓고 며칠씩 붙잡는 상황이 반복된다면 이 사례가 맞습니다. 포스트잇에 발언을 하나씩 옮겨 벽에 붙이고(어피니티 다이어그램), 비슷한 것끼리 묶고, 리포트에 넣을 인용을 다시 녹취록에서 찾아 오타 없이 옮기는 일 — 이 과정이 매번 이틀에서 사흘을 먹습니다. 문제는 매 분기 형식이 거의 같다는 것입니다. 형식이 반복되는 일이야말로 팀(하네스)으로 자동화할 값어치가 있습니다.

참고: 2025년 User Interviews의 조사에서 리서처의 80%가 이미 AI 도구를 쓰고 있고, 그중에서도 "분석·종합" 단계가 AI 효용이 가장 큰 구간으로 꼽혔습니다(아래 출처). 이 사례는 그 흐름을 개인 도구 구독이 아니라 내가 소유하는 에이전트 팀으로 만드는 방법입니다.

팀 미리보기

하네스가 만들어 줄 팀은 이렇습니다:

팀원 역할
collector (수집·정리) 녹취 파일들을 읽어 발언을 화자·시점 단위로 잘라 정리. 잡음(인사말·중복)을 걸러냄
clusterer (어피니티 그룹핑) 정리된 발언을 주제별로 묶어 상위 테마 → 하위 테마 구조를 만듦
quote-verifier (인용 검증) 리포트에 쓸 인용문이 원본 녹취록에 실제로 있는 문장인지 대조. 없는 말은 표시
reporter (인사이트 리포트) 테마별 인사이트 + 검증된 인용 + 근거 개수를 마크다운(제목·표로 구조화된 텍스트 형식) 리포트로 작성

검증 담당(quote-verifier)을 팀에 넣는 것이 핵심입니다. AI가 리서치를 종합할 때 가장 위험한 실수가 "그럴듯하지만 아무도 하지 않은 말"을 인용으로 지어내는 것(환각)이기 때문입니다.

따라 하기

0단계: 하네스 설치 확인 (처음 한 번만)

이 사례는 revfactory/harness가 설치되어 있어야 합니다. 설치는 전체 사례집을 통틀어 처음 한 번만 하면 됩니다 — 아직이라면 하네스 설치 안내를 따라 하세요 (약 2분).

  • 설치 확인: Claude Code 대화창에 /plugin을 입력해 목록에 harness가 보이면 준비 완료. 이미 설치했다면 바로 1단계로 넘어갑니다.

1단계: 준비

화면에서 이렇게 합니다:

  1. 작업할 폴더를 하나 만듭니다. 예: 바탕화면에 2026Q3_인터뷰종합 폴더.
  2. 그 안에 input 폴더를 만들고, 인터뷰 녹취 텍스트 파일을 전부 넣습니다. - 파일은 .txt 나 .md(마크다운, 제목·목록을 기호로 표시하는 텍스트 형식) 로. 워드·PDF라면 "다른 이름으로 저장 → 텍스트"로 바꿔 넣으면 됩니다. - 파일명에 화자를 적어두면 좋습니다. 예: P01_30대여성_앱결제.txt
  3. 그 폴더 안에서 Claude Code를 실행합니다. "폴더 안에서 실행"이란 터미널을 그 폴더로 이동시킨 뒤 여는 것을 말합니다. - macOS: Spotlight(⌘+Space)에 terminal을 입력해 터미널(검은 명령어 입력 창)을 엽니다 → 창에 cd를 입력하고 한 칸 띄운 뒤, 만든 폴더를 터미널 창 안으로 드래그하면 경로가 자동 입력됩니다(예: cd /Users/나/Desktop/2026Q3_인터뷰종합) → Enter → claude 입력 후 Enter를 누르면 Claude Code가 켜집니다. (Finder 우클릭 → 서비스 → '폴더에서 새로운 터미널 열기' 메뉴가 보인다면 그걸 써도 됩니다 — 단, 이 메뉴는 기본값으로 꺼져 있는 Mac이 많습니다.) - Windows: 폴더를 연 상태에서 위쪽 주소창을 클릭해 cmd라고 입력하고 Enter를 누르면, 그 폴더 위치에서 명령어 창이 열립니다. 열린 창에 claude라고 입력하고 Enter를 누릅니다.

녹취록 한 개의 내부는 이런 모습이면 충분합니다. 형식이 완벽할 필요는 없습니다:

복사해서 쓰세요
[P01] 결제까지 갔는데 배송비가 마지막에 붙어서 좀 배신감 들었어요.
[진행자] 그때 어떻게 하셨어요?
[P01] 그냥 장바구니에 두고 나왔죠. 다른 데랑 비교하려고.

2단계: 팀 구성 (바이브코딩 — 코드를 직접 쓰지 않고 말로 팀을 설계하는 방식)

아래를 복사해 붙여넣고, {중괄호} 부분만 여러분 상황으로 바꾸세요:

복사해서 쓰세요
하네스 구성해줘: 사용자 인터뷰 녹취록을 종합하는 리서치 분석 팀이 필요해.
input 폴더의 녹취 텍스트 파일들을 입력하면,
(1) 발언을 화자·시점 단위로 정리하고
(2) 어피니티 그룹핑으로 주제별 테마를 묶고
(3) 리포트에 넣을 인용문이 원본 녹취록에 실제로 있는지 대조 검증하고
(4) 테마별 인사이트 + 검증된 인용 + 근거 개수가 담긴 인사이트 리포트를 마크다운으로 저장
해주는 팀으로. 우리 제품은 {모바일 커머스 앱}이고, 이번 인터뷰 주제는 {결제·이탈 경험}이야.
검증에서 원본 녹취록에 실제로 있는 인용은 ✅검증됨으로, 원본에 없는 인용은 ⚠️[출처 불명]으로 각각 표시하도록 해줘.

잠시 후 .claude/agents/ 폴더에 팀원 파일들(collector.md, clusterer.md, quote-verifier.md, reporter.md 같은)이, .claude/skills/ 폴더에 팀의 작업 방법과 오케스트레이터(팀 전체를 순서대로 지휘하는 지휘자 역할 스킬)가 생깁니다.

확인은 따로 파일을 뒤질 필요 없습니다. 하네스가 마지막에 "이런 팀을 만들었습니다" 요약과 팀원 표, 그리고 실행할 때 쓸 문구를 알려줍니다. 그 문구를 다음 단계에서 씁니다.

3단계: 팀 실행

하네스가 알려준 실행 문구를 대화창에 붙여넣습니다. 같은 대화창에서 이어서 입력해도 되고, 대화가 길어졌다면 새 세션에서 입력해도 됩니다(새 세션은 대화창에 /clear 를 입력하거나 claude 를 다시 실행하면 시작됩니다). 보통 이런 형태입니다:

복사해서 쓰세요
인터뷰 종합 실행해줘. input 폴더의 녹취록으로 이번 분기 인사이트 리포트 만들어줘.

팀이 순서대로 일하고, 이런 식의 리포트가 나옵니다(축약 실물):

복사해서 쓰세요
# 2026 Q3 사용자 인터뷰 인사이트 리포트
분석 대상: 녹취 10건 / 발언 214개 / 도출 테마 5개

## 테마 1. 결제 마지막 단계의 '숨은 비용' 충격 (근거 발언 18개 / 참여자 7명)
결제 직전 배송비·수수료가 처음 드러나며 이탈로 이어짐.
- "배송비가 마지막에 붙어서 배신감 들었어요" — P01 ✅검증됨
- "총액이 갑자기 바뀌니까 다시 계산하게 돼요" — P04 ✅검증됨

## 테마 2. 로그인 요구 시점에 대한 거부감 (근거 발언 12개 / 참여자 5명)
- "구경만 하려는데 로그인부터 하래서 나갔어요" — P03 ✅검증됨
- "게스트 결제가 어디 있는지 못 찾았어요" — P07 ⚠️[출처 불명 — 원본 미확인, 사람 확인 필요]

## 우선 대응 제안 (근거 많은 순)
1. 배송비를 상품 단계에서 미리 노출 (테마 1, 근거 18개)
2. 게스트 결제 진입점 강화 (테마 2, 근거 12개)

⚠️[출처 불명] 표시가 검증 담당이 걸러낸 부분입니다 — 여러분이 원본을 확인해 살릴지 뺄지 결정하는 지점입니다.

4단계: 팀 다듬기 (진화)

결과에서 아쉬운 부분은 팀에게 말로 피드백합니다:

  • 하네스 회고: 테마를 5개로 뭉뚱그리지 말고, 근거 발언 3개 이상인 테마는 다 남기는 방향으로 clusterer 개선해줘.
  • 하네스 회고: 리포트 맨 위에 경영진용 3줄 요약을 넣도록 reporter에 추가해줘.

다음 실행부터 반영됩니다. 구축은 1회, 실행은 매번 — 다음 분기에는 input 폴더의 파일만 새 녹취록으로 바꿔 넣고 3단계 문구를 다시 실행하면 됩니다.

꼭 사람이 확인하세요

  • 인용의 진위(가장 중요). 검증 담당이 있어도 100%는 아닙니다. ✅검증됨 표시도 최소한 리포트에 실제로 인용한 문장들은 원본에서 눈으로 한 번 확인하세요. AI는 그럴듯한 말을 지어내는 경향(환각)이 있습니다.
  • 뉘앙스와 반어. "아 진짜 좋네요"가 칭찬인지 비꼼인지, 침묵·망설임의 의미 같은 것은 AI가 놓칩니다. 테마 해석은 사람이 감수하세요.
  • 테마의 과잉 단순화. AI는 깔끔하게 5개로 묶고 싶어 합니다. 소수 의견(근거 1~2개)이 오히려 중요한 신호일 수 있으니, 버려진 발언 목록도 한 번 훑어보세요.
  • 참여자 수 vs 발언 수 혼동. "발언 18개"와 "참여자 7명"은 다릅니다. 한 사람이 같은 불만을 반복하면 발언 수가 부풀 수 있으니 참여자 기준도 함께 보세요.

하네스가 과한 경우

인터뷰가 이번 한 번뿐이고 3~4건 규모라면 팀을 만들 필요가 없습니다. 녹취록을 Claude Code 대화창에 붙여넣고 이렇게 한 번 물어보는 게 더 빠릅니다:

복사해서 쓰세요
이 인터뷰 녹취록 4건을 주제별로 묶어서 테마와 대표 인용을 정리해줘.
인용은 원문에 있는 문장만 쓰고, 확실하지 않으면 표시해줘.

판단 기준은 단 하나입니다: 같은 형식의 리포트가 앞으로도 반복해서 필요한가? 분기마다·프로젝트마다 돌아온다면 하네스, 한 번 쓰고 말 것이면 프롬프트 한 번.

한 걸음 더

  • 페르소나 팀과 연결. 이 팀의 리포트를 그대로 다음 하네스(persona-journey 영역)의 입력으로 넘기면, 종합 → 페르소나 → 저니맵까지 이어집니다.
  • 검증 담당 강화. quote-verifier에 "인용마다 원본 파일명과 줄 위치를 함께 표기"를 추가하면 추적성(어떤 인용이 어느 녹취록에서 왔는지 되짚는 성질)이 올라갑니다. 상용 도구들이 강조하는 기능을 내 팀에도 넣는 셈입니다.
  • 처음부터 안 만들어도 됩니다. revfactory/harness-100에 리서치 관련 팀 하네스가 이미 있으니, 가까운 것을 설치해 우리 인터뷰 형식에 맞게 고쳐 쓰는 것이 더 빠른 출발점일 수 있습니다.
  • 심화 도전. .claude/agents/clusterer.md를 직접 열어, 그룹핑 기준(예: "Jobs-to-be-Done 관점 — 사용자가 이루려는 과업 기준으로 묶어라")을 한 줄 추가해 보세요. 팀 구조를 손수 조정하는 감각이 생깁니다.
