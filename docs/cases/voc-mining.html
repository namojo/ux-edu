앱 리뷰·CS 티켓 수백 건에서 개선 기회 뽑아내기

따라 하기리뷰·CS 티켓 수백 건에서 개선 기회를 찾을 때
항목 내용
영역 VoC/CX 피드백 분석
난이도 중급
소요 시간 약 30~40분
준비물 앱스토어/구글플레이 리뷰 또는 CS 티켓을 모은 텍스트 파일 1개(엑셀에서 복사한 표도 가능), Claude Code가 설치된 컴퓨터(설치가 안 되어 있다면 사내 위키 › AI 도구 › Claude Code 설치를 먼저 참고하세요. 배포 전 실제 링크로 치환)

이런 상황에서 쓰세요

분기마다 앱 리뷰 300건, CS 인입 티켓 500건이 쌓이는데 "그래서 뭘 고쳐야 하죠?"라는 질문에 답하려면 며칠씩 눈으로 읽으며 포스트잇에 옮겨 적어야 합니다. 별점은 떨어졌는데 원인이 결제 오류인지, 배송 지연인지, 로그인 불편인지 한눈에 안 잡힙니다. 사람이 다 읽고 분류하면 정확하지만 느리고, 중간에 지쳐서 뒤쪽 리뷰는 대충 보게 됩니다. 이 작업을 AI에게 1차로 맡기고, 사람은 검토·판단에만 집중하는 방법입니다.

업계에서도 같은 방향으로 갑니다: 최근 VoC(Voice of Customer, 고객의 소리) 분석 도구들은 수천 건의 리뷰를 몇 분 만에 주제·감정별로 자동 묶어 주는 기능을 기본 탑재하고 있습니다. 다만 공통된 권고는 "AI로 대체가 아니라 보강"입니다 — AI는 패턴을 빠르게 찾아주지만 사람처럼 의미·맥락을 진짜로 이해하지는 못하기 때문에, 초벌 분류는 AI에게 맡기고 해석·판단은 사람이 한다는 원칙입니다(Thematic, 2025 가이드). 아래 절차가 정확히 그 구조입니다.

따라 하기

1단계: 준비

먼저 분석할 피드백을 하나의 텍스트 파일로 모읍니다.

  1. 바탕화면이나 문서 폴더에 작업용 폴더를 하나 만듭니다. 예: voc-2026-2분기
  2. 앱 리뷰나 CS 티켓을 그 폴더 안에 reviews.txt(그냥 메모장/텍스트편집기로 만든 파일)로 저장합니다. 엑셀에 있다면 리뷰 내용 열을 통째로 복사해 붙여넣으면 됩니다. 형식은 자유지만, 리뷰 하나가 한 줄 또는 한 문단으로 구분되어 있으면 좋습니다. - 별점 기반 분석(예: "낮은 별점에 어떤 불만이 몰리는지")을 원한다면, 리뷰 내용 열만 복사하지 말고 별점 열도 반드시 함께 복사하세요. 파일에 별점이 없으면 아래 프롬프트의 4번(부정 리뷰 분석)은 건너뛰게 됩니다. 별점·날짜·기기 정보가 함께 있으면 그대로 두면 됩니다.
  3. 터미널(명령어를 입력하는 검은 창)을 열고, 위에서 만든 작업용 폴더로 이동한 뒤 claude 를 입력해 Claude Code를 켭니다. Claude Code는 지금 있는 폴더 안의 파일을 읽고 쓰는 AI 도구라서, 반드시 reviews.txt가 들어 있는 폴더 안에서 켜야 합니다. - 폴더로 이동하는 가장 쉬운 방법: Mac은 Finder에서 그 폴더를 우클릭 → "폴더에서 새로운 터미널 열기"를 누르면 이동이 끝난 상태로 터미널이 열립니다. Windows는 파일 탐색기에서 그 폴더를 연 뒤 위쪽 주소창에 cmd를 입력하고 Enter를 누르면 됩니다. - 명령어로 이동하려면: 터미널에 cd(폴더 이동 명령) 뒤에 폴더 경로를 적습니다. 예: cd Desktop/voc-2026-2분기 를 입력하고 Enter. 경로는 폴더를 만든 위치에 맞추세요(문서 폴더에 만들었다면 cd Documents/voc-2026-2분기). 잘 들어왔는지 모르겠으면 ls(폴더 안 파일 목록 보기)를 입력해 reviews.txt가 보이는지 확인하세요.

개인정보 주의: 리뷰·티켓에 고객 이름, 전화번호, 주문번호가 들어 있다면 붙여넣기 전에 지우거나 가립니다(예: 전화번호를 010-****-****로). 이유는 아래 "꼭 사람이 확인하세요"에서 다시 짚습니다.

2단계: 프롬프트 입력

아래를 복사해 붙여넣고, {중괄호} 부분만 바꾸세요:

복사해서 쓰세요
reviews.txt 파일을 읽어줘. 이건 {우리 쇼핑 앱}의 {2026년 2분기} 사용자 리뷰/CS 티켓 모음이야.

다음을 해줘:
1. 리뷰들을 내용 주제별로 분류해줘. 주제는 미리 정하지 말고 실제 내용에서 자연스럽게 묶어서 5~8개 정도로 만들어줘.
2. 각 주제마다: (a) 주제 이름, (b) 해당 리뷰 대략 몇 건인지(전체 대비 비율도), (c) 대표 리뷰 원문 2개를 그대로 인용, (d) 사용자가 겪는 핵심 불편 한 문장 요약.
3. 표로 정리하고, 건수가 많은 주제부터 위로 정렬해줘.
4. (파일에 별점이 함께 있을 때만) 별점이 낮은(부정적인) 리뷰에서 특히 두드러지는 주제 3개를 따로 짚어줘. 별점 정보가 파일에 없으면 이 항목은 건너뛰고, 별점이 없다고 알려줘 — 별점을 임의로 추측하지는 마.

원문에 없는 내용은 절대 지어내지 말고, 판단이 애매한 리뷰는 '분류 애매'로 따로 빼줘.

3단계: 결과 확인

이런 식의 결과가 나옵니다(내용은 예시입니다):

순위 주제 건수(비율) 핵심 불편 요약
1 결제/쿠폰 오류 82건 (27%) 쿠폰 적용 후 결제 단계에서 금액이 원래대로 돌아옴
2 배송 지연·추적 61건 (20%) 발송 알림은 왔는데 며칠째 배송 상태가 안 바뀜
3 로그인/인증 44건 (15%) 재설치하면 매번 본인인증을 다시 해야 함

프롬프트 2번에서 요청한 (c) 대표 리뷰 원문은 표가 너무 길어지지 않도록 표 자체에는 넣지 않고, 표 아래에 주제별로 따로 인용됩니다(이 페이지 맨 아래 예시 참고). 그리고 프롬프트 4번(별점 기반 분석)은 파일에 별점이 있을 때만 아래처럼 나옵니다.

부정 리뷰에서 두드러진 주제 - 결제/쿠폰 오류: 1~2점 리뷰의 절반 가까이가 여기 몰려 있음 → 별점 하락의 최대 원인일 가능성 - 고객센터 연결: "챗봇만 돌고 상담원 연결이 안 된다"는 불만이 부정 리뷰에 집중 - 앱 강제 종료: 특정 기종(예: 갤럭시 구형)에서 반복 언급

그리고 각 주제마다 대표 리뷰 원문 2개가 그대로 인용되어 나옵니다. 예:

"쿠폰 넣으면 3천원 할인된다고 나오는데 막상 결제하면 정가로 빠져나가요. 두 번이나 이럼." (★1)

4단계: 다듬기

첫 결과가 나오면 후속 프롬프트로 원하는 각도로 좁혀 갑니다. 아래처럼 이어서 입력하면 됩니다:

  • 1번 '결제/쿠폰 오류' 주제만 더 파줘. 이 안에서도 세부 유형으로 다시 3~4개로 나누고, 각 유형별 대표 리뷰를 붙여줘.
  • 이 결과를 표 그대로 improvement.md 파일로 저장해줘. 그리고 각 주제마다 "예상 개선 방향" 열을 하나 더 추가해줘 — 단, 이건 제안이라는 걸 표시해줘.

두 번째처럼 파일로 저장(improvement.md는 마크다운, 즉 표·제목을 기호로 표현한 텍스트 파일)해 두면 회의 자료로 바로 공유하거나 다음 분기에 비교할 수 있습니다.

꼭 사람이 확인하세요

  • 건수·비율은 반드시 대략치로 받아들이세요. AI가 리뷰를 주제로 묶는 과정에서 경계가 애매한 것을 한쪽에 몰아넣을 수 있어, "27%"가 정확한 통계는 아닙니다. 순위(무엇이 더 큰 문제인지)는 신뢰하되, 숫자를 그대로 KPI로 옮기지 마세요.
  • 인용이 진짜 원문인지 한 번 검증하세요. AI는 그럴듯하게 문장을 다듬거나 아예 없는 내용을 지어낼 수 있습니다. 이것을 환각(hallucination, AI가 사실이 아닌 것을 사실처럼 자신 있게 말하는 현상)이라고 합니다. 실제 앱 리뷰를 분석한 연구에서도 가장 많이 보고된 환각 유형이 '사실과 다른 서술'(38%)과 '없는 정보 지어내기'(15%)였습니다(Nature Scientific Reports, 2025). 그러니 대표 인용 몇 개는 reviews.txt에서 실제로 검색해(엑셀·메모장의 찾기 기능 Ctrl+F/Cmd+F) 글자 그대로 있는지 확인하세요. 없거나 살짝 바뀌었다면 "원문 그대로만 인용해"라고 다시 지시합니다.
  • 개선 방향 제안은 아이디어일 뿐입니다. 4단계에서 붙인 "예상 개선 방향"은 AI 추측이므로, 실제 원인 분석·개발 검토 없이 실행 계획으로 확정하지 마세요.
  • 개인정보가 남아 있지 않은지 결과에서도 확인하세요. 원문 인용에 고객 이름·주문번호가 딸려 나올 수 있습니다. 공유 전에 가립니다.
  • 소수 의견이 묻히지 않게 보세요. 주제로 묶으면 건수 1~2건짜리 심각한 안전·보안 이슈가 "기타"로 사라질 수 있습니다. '분류 애매'와 소수 주제도 한 번 훑으세요.

한 걸음 더

이 분석이 매 분기·매월 반복된다면, 매번 프롬프트를 붙여넣는 대신 에이전트 팀(하네스) 으로 승격할 가치가 있습니다. 하네스는 역할이 나뉜 AI들이 순서대로 일하는 작은 팀입니다. 예를 들어:

  • 수집 담당: 앱스토어·CS 툴에서 이번 기간 리뷰를 모아 하나의 파일로 정리
  • 분류 담당: 위 2단계 프롬프트를 고정 규칙으로 실행해 주제별 표 생성
  • 검증 담당: 인용문이 원문에 실제로 있는지 대조하고 개인정보가 남았는지 점검
  • 리포트 담당: 지난 분기 결과와 비교해 "새로 늘어난 주제"를 강조한 요약본 작성

이렇게 만들어 두면 다음 분기에는 파일만 넣고 실행하면 같은 품질의 리포트가 나옵니다. "매번 같은 방식으로, 같은 형식의 결과가 필요하다"가 반복될 때가 하네스로 만들 시점입니다.

이렇게 역할을 나눠 순서대로 검증까지 태우는 방식(사람이 각 단계 결과를 확인하는 "휴먼 인 더 루프", human-in-the-loop)은 AI 실무에서 실수를 조기에 잡는 표준 패턴으로 권장됩니다 — 한 프롬프트로 다 끝내려 하기보다, 분류 → 검증 → 리포트로 쪼갤수록 환각이 최종 산출물까지 흘러갈 확률이 줄어듭니다.

참고: 업계 동향

  • AI 자동 주제 분류는 이미 VoC 분석의 표준 기능입니다. Thematic, SentiSum 등 고객 피드백 분석 도구들은 수천 건을 몇 분 만에 주제·감정·긴급도별로 자동 분류합니다. 이 사례는 그 작업을 별도 도구 구독 없이 Claude Code로 재현하는 방법입니다.
  • 공통 권고는 "대체가 아닌 보강"입니다. AI는 초벌 코딩(분류)과 요약에는 강하지만 의미·뉘앙스 이해는 사람에 못 미칩니다. 그래서 위 사례도 AI에게 1차 분류를, 사람에게 해석·판단을 맡깁니다.
