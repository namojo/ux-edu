# VoC 분석 팀을 만들어 분기 리포트 자동화하기

| 항목 | 내용 |
|------|------|
| 영역 | VoC/CX 피드백 분석 |
| 난이도 | 중급 (구성 → 실행 → 피드백 루프까지) |
| 소요 시간 | 구축 약 20분 (처음 한 번) + 실행 회당 약 10분 (분기마다) |
| 준비물 | 리뷰/피드백 텍스트 파일, revfactory/harness 설치 (아래 0단계) |
| 팀 패턴 | Pipeline(순차 처리 — 수집→분류→검증→리포트를 한 줄로 흘려보내는 조립 라인 방식) |

## 이런 상황에서 쓰세요

분기가 끝날 때마다 앱스토어 리뷰, CS 티켓, 설문 자유응답을 한데 모아 "이번 분기 고객은 무엇에 불만이었나"를 정리하시나요? 수백~수천 건을 스프레드시트에 붙여 넣고, 눈으로 읽어 주제별로 색칠하고, 인용할 문장을 고르고, 전 분기와 비교하는 데 꼬박 이틀이 걸립니다. 그런데 이 작업은 **형식이 매번 똑같습니다.** 데이터만 바뀔 뿐 "분류 → 인용 → 비교 → 리포트"라는 골격은 분기마다 동일합니다.

바로 이 "형식은 고정, 데이터만 교체"가 하네스(에이전트 팀을 자동으로 만들어 주는 도구)를 쓸 최적의 조건입니다. **한 번 팀을 만들어 두면, 다음 분기부터는 파일만 갈아 끼우고 실행 버튼만 누르면 됩니다.**

## 팀 미리보기

하네스가 만들어 줄 팀은 이렇습니다:

| 팀원 | 역할 |
|------|------|
| collector (수집·정제) | 여러 파일에 흩어진 리뷰를 하나로 모으고, 빈 줄·중복·깨진 문자를 정리해 분석 가능한 형태로 만든다 |
| classifier (주제 분류) | 각 피드백을 주제(예: 로그인 오류, 배송 지연, 가격 불만)로 태깅하고 긍정/부정 감정을 판정한다 |
| verifier (인용·개인정보 검증) | 리포트에 넣을 인용문이 원문에 실제로 있는지 대조하고(환각 방지), 이름·전화번호·이메일 같은 개인정보를 가린다 |
| reporter (분기 비교 리포트) | 이번 분기 주제 분포를 전 분기와 비교해 "무엇이 늘고 줄었는지" 표와 요약으로 정리한다 |

> 이 팀에는 **검증 담당(verifier)이 따로 있는 것**이 핵심입니다. AI는 그럴듯한 인용문을 지어내거나(환각), 개인정보를 무심코 리포트에 노출할 수 있습니다. 생성하는 팀원과 검증하는 팀원을 나눠 두면 이 위험을 구조적으로 줄일 수 있습니다.

## 따라 하기

### 0단계: 하네스 설치 (처음 한 번만)

Claude Code(터미널에서 대화하듯 쓰는 AI 코딩 도구) 대화창에 아래 두 줄을 차례로 입력합니다. 이미 설치했다면 건너뛰세요.

```
/plugin marketplace add revfactory/harness
/plugin install harness@harness-marketplace
```

### 1단계: 준비

1. 컴퓨터에 작업 폴더를 하나 만듭니다. 예: `voc-2026-2분기`
2. 그 안에 분석할 텍스트를 파일로 넣습니다. 형식은 자유지만 아래처럼 **한 건당 한 줄** 또는 CSV(쉼표로 칸을 나눈 표 형식 파일)면 팀이 읽기 편합니다.
   - `reviews_appstore.txt` (앱스토어 리뷰)
   - `tickets_cs.csv` (CS 티켓 — 날짜, 채널, 내용 열)
   - `survey_freetext.txt` (설문 자유응답)
3. 비교할 **전 분기 리포트**가 있다면 같은 폴더에 `voc-2026-1분기-리포트.md`처럼 넣어 둡니다. (없으면 이번이 첫 기준선이 됩니다.)
4. 터미널(컴퓨터에 명령을 글로 입력하는 검은 창)에서 이 폴더를 열고 Claude Code를 켭니다.

### 2단계: 팀 구성 (바이브코딩 — 코드 대신 말로 팀을 설계하기)

아래를 복사해 붙여넣고, {중괄호} 부분만 여러분 상황에 맞게 바꾸세요:

```
하네스 구성해줘: 앱 리뷰와 CS 티켓, 설문 자유응답을 분석하는 VoC 분석 팀이 필요해.
{여러 개의 텍스트/CSV 파일}을 입력하면,
(1) 하나로 모아 정제하고
(2) 주제별로 분류하고 감정(긍정/부정)을 판정하고
(3) 리포트에 넣을 인용문이 원문에 실제로 있는지 검증하고 개인정보를 가리고
(4) 전 분기 리포트와 비교해서 어떤 주제가 늘고 줄었는지 표로 정리하는
팀으로 만들어줘. 최종 결과는 1페이지 요약 + 상세로 나눈 마크다운 리포트로 저장해줘.
```

> **마크다운**: 제목·표·목록을 기호 몇 개로 표현하는 가벼운 문서 형식입니다. 워드처럼 열어 볼 수 있고, 그대로 사내 위키에 붙여 넣기 좋습니다.

잠시 후 `.claude/agents/` 폴더에 팀원 파일들(collector, classifier, verifier, reporter)이, `.claude/skills/`에 팀의 작업 방법과 이들을 순서대로 지휘하는 오케스트레이터(팀장 역할 스킬)가 생깁니다. 하네스가 **마지막에 팀 구성 요약과 "이렇게 실행하세요"라는 트리거 문구를 알려 줍니다** — 그 문장을 그대로 기억해 두면 됩니다.

### 3단계: 팀 실행

구성이 끝났으면 새 대화(새 세션)를 열어 실행합니다 — 팀 만들기와 팀 돌리기를 분리하면 동작이 깔끔합니다(새 세션은 대화창에 /clear 를 입력하거나 claude 를 다시 실행하면 시작됩니다). 하네스가 알려 준 트리거 문구(예: 아래)를 입력하면 팀이 순서대로 일을 시작합니다:

```
VoC 분석 실행해줘. 이번 분기 폴더는 voc-2026-2분기, 비교 대상은 1분기 리포트야.
```

이런 식의 결과가 나옵니다 (축약 실물):

```markdown
# VoC 분기 리포트 — 2026년 2분기

## 한눈에 보기 (1페이지 요약)
- 분석 건수: 1,842건 (앱리뷰 약 1,200 · CS 약 640 · 설문 소량)
- 부정 피드백 비중: 58% (전 분기 51% → 7%p 증가)
- 가장 커진 주제: "로그인·인증 오류" (12% → 21%, 최다 급증)
- 가장 줄어든 주제: "배송 지연" (18% → 9%)

## 주제별 분포 (전 분기 대비)
| 주제 | 2분기 | 1분기 | 변화 | 감정 |
|------|-------|-------|------|------|
| 로그인·인증 오류 | 21% | 12% | ▲ +9%p | 부정 94% |
| 앱 속도·멈춤 | 16% | 14% | ▲ +2%p | 부정 88% |
| 배송 지연 | 9% | 18% | ▼ −9%p | 부정 79% |
| 가격·혜택 | 8% | 9% | − −1%p | 혼재 |

## 대표 인용 (원문 대조 완료 · 개인정보 가림 처리)
- 로그인 오류: "지문 로그인이 3번 중 1번은 실패해요. 매번 비번 치기 번거로워요" (앱리뷰, ★2)
- 배송 지연: "이번엔 예정일에 딱 왔어요. 지난번보다 훨씬 나아졌네요" (CS, 긍정)

## 상세 분석
...(주제별 세부 내역, 채널별 교차표 등)
```

리포트는 작업 폴더(예: `voc-2026-2분기`) 안에 마크다운 파일로 저장됩니다. 실행이 끝나면 하네스가 저장 위치와 파일명을 알려 주니 그 파일을 열어 보세요.

### 4단계: 팀 다듬기 (진화)

결과가 아쉬운 부분은 팀에게 말로 피드백합니다. 코드를 고치는 게 아니라 대화로 개선합니다:

- `하네스 회고: 주제 분류가 너무 뭉뚱그려져. "로그인·인증 오류"를 "지문/얼굴 인증 실패"와 "비밀번호 관련"으로 더 잘게 나누도록 classifier를 개선해줘.`
- `하네스 회고: 요약이 아직 길어. 경영진 보고용이니 1페이지 맨 위에 "이번 분기 핵심 3줄"을 먼저 넣도록 reporter를 개선해줘.`

다음 실행부터 반영됩니다. **구축은 1회, 실행은 매번** — 다음 3분기에는 `voc-2026-3분기` 폴더에 새 파일만 넣고 3단계 문장만 다시 입력하면 됩니다.

## 꼭 사람이 확인하세요

- **인용문 진위**: verifier가 원문 대조를 하지만, 100% 신뢰하지 말고 리포트에 실을 대표 인용 몇 개는 사람이 원문에서 직접 눈으로 확인하세요. AI는 여러 문장을 매끄럽게 합치면서 원문에 없는 표현을 섞을 수 있습니다.
- **주제 분류의 경계**: "가격 불만"인지 "혜택 축소 불만"인지처럼 미묘한 구분은 AI가 팀 기준과 다르게 나눌 수 있습니다. 분포 표에서 비중이 큰 상위 3~4개 주제는 실제 원문 몇 건을 표본으로 열어 분류가 맞는지 점검하세요.
- **감정 판정의 반어·비꼼**: "정말 훌륭한 서비스네요, 3일째 답이 없는데"처럼 반어적 표현을 AI가 긍정으로 오판할 수 있습니다. 부정률이 급변한 분기에는 특히 표본 검토가 필요합니다.
- **개인정보 마스킹**: verifier가 이름·연락처를 가리지만, "우리 아파트 3동 사는데"처럼 간접 식별 정보는 놓칠 수 있습니다. 외부 공유 전 사람이 최종 검토하세요.
- **표본 편향**: 앱스토어 리뷰는 극단적 의견(★1, ★5)에 쏠립니다. 리포트의 부정 비중을 "전체 고객의 목소리"로 곧장 해석하지 말고, 채널별 특성을 감안해 읽으세요.

## 하네스가 과한 경우

이번 한 번만 리뷰 50건을 훑어 대략의 불만 주제만 파악하면 되는 상황이라면, 팀을 만들 필요가 없습니다. 파일 하나를 열어 두고 이렇게 한 번 물어보는 게 빠릅니다:

```
이 리뷰 파일을 읽고 불만 주제를 많은 순으로 5개만 뽑아서, 각 주제별 대표 문장 1개씩 알려줘.
```

**판단 기준은 반복성입니다.** "이번에만"이면 프롬프트 한 번, "분기마다 같은 형식으로"면 하네스. 이 VoC 리포트처럼 매 분기 동일한 골격을 반복한다면, 20분 투자해 팀을 만들어 두는 편이 매번 이틀을 쓰는 것보다 훨씬 남습니다.

## 한 걸음 더

- **채널 추가**: 인스타 댓글, 커뮤니티 글 등 소스가 늘면 `하네스 회고: 소셜 댓글 CSV도 입력에 포함하도록 collector를 확장해줘`로 팀을 키웁니다.
- **자동 알림 연결(심화)**: reporter 뒤에 "부정 급증 주제를 슬랙에 요약 전송" 팀원을 추가하는 구조로 확장할 수 있습니다. 여기서부터는 팀 구조를 직접 손보는 심화 영역입니다.
- **가까운 하네스에서 출발**: 처음부터 만들지 않고, [revfactory/harness-100](https://github.com/revfactory/harness-100)(10개 도메인 100개 팀 하네스 모음)에서 비슷한 피드백 분석 팀을 설치해 수정하는 방법도 있습니다.
