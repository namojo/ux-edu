# 첫 하네스 치트시트 — `first-harness`

한 장으로 보는 오늘의 명령어·판단 기준. 인쇄해 책상에 두고 참고하세요.

---

## 1. 설치 확인 (설치는 `first-contact`에서 이미 완료 — 전체 교육에서 한 번만)

- 확인: 대화창에 `/plugin` 입력 → 목록에 `harness`가 보이면 준비 완료
- 안 보이면: `first-contact` 가이드의 **하네스 설치** 단계 참조 (또는 TA 호출)

---

## 2. 트리거 문구 (바이브코딩 진입점)

| 하고 싶은 것 | 입력 문구 |
|---|---|
| 새 팀 만들기 | **"하네스 구성해줘"** + 무엇을 하는 팀인지 + 입력 + 원하는 산출물 |
| 만든 팀 실행하기 | 하네스가 구성 마지막에 알려준 **오케스트레이터 트리거 문구** 그대로 (세션마다 문구를 새로 확인) |
| 팀 개선하기(진화) | **"하네스 회고:"** + 아쉬운 점 + 어떻게 고쳤으면 하는지 |

**좋은 구성 프롬프트의 형태** — 무엇을 하는 팀인지 + 입력 + 원하는 산출물, 이 세 가지가 들어가야 합니다.

```
하네스 구성해줘: {무엇을 분석/처리하는 팀}이 필요해.
{입력 파일 형태}을 입력하면,
(1) ~하고 (2) ~하고 (3) ~하는
팀으로 만들어줘. 결과는 {원하는 산출물 형식}으로 저장해줘.
```

오늘 실습에 쓴 실제 문구(참고용):

```
하네스 구성해줘: 고객 리뷰를 분석하는 팀이 필요해.
리뷰 텍스트 파일을 입력하면,
(1) 리뷰를 모아 정리하고
(2) 불만/칭찬 주제별로 분류하고
(3) 리포트에 넣을 대표 인용문이 원문에 실제로 있는지 검증하고
(4) 주제별 건수와 대표 인용을 정리한 리포트를 만들어주는
팀으로 만들어줘. 최종 결과는 마크다운 파일로 저장해줘.
```

---

## 3. 하네스가 만드는 것

```
내 작업 폴더/
├── .claude/
│   ├── agents/   ← 팀원 정의 파일 (예: collector.md, verifier.md, reporter.md)
│   └── skills/   ← 팀의 작업 방법 + 오케스트레이터(팀장 역할)
```

**구축은 1회, 실행은 반복** — 팀은 한 번만 만들고, 그다음부터는 트리거 문구로 몇 번이든 돌립니다.

---

## 4. 팀 아키텍처 6패턴 (한 줄 요약)

| 패턴 | 한 줄 요약 |
|---|---|
| Pipeline | 수집→분석→리포트를 한 줄로 순서대로 흘려보낸다 |
| Fan-out/Fan-in | 여러 관점으로 동시에 나눠 분석한 뒤 하나로 합친다 |
| Expert Pool | 필요할 때마다 맞는 전문 담당을 골라 부른다 |
| Producer-Reviewer | 만드는 담당과 검증하는 담당을 나눈다 (오늘 실습 팀이 이 구조) |
| Supervisor | 상황에 따라 일을 동적으로 나눠 준다 |
| Hierarchical | 위에서 아래로 계층적으로 위임한다 |

> UX 실무에서 가장 자주 쓰는 것: **Fan-out/Fan-in**(다관점 분석), **Producer-Reviewer**(초안-검수), **Pipeline**(수집→분석→리포트).

---

## 5. "프롬프트냐 팀이냐" 판단 기준

아래 3가지 중 **2가지 이상**에 해당하면 하네스(팀)를 만드는 편이 이득입니다. 1가지 이하면 프롬프트 한 번으로 끝내세요.

| 판단 항목 | 질문 |
|---|---|
| ① 반복성 | 이번 한 번이 아니라 매주/매달/매분기 되풀이되는 일인가? |
| ② 형식 고정 | 매번 같은 틀(표·항목)로 정리해야 하는가? |
| ③ 검증 필요 | 인용·수치·개인정보처럼 사람이 매번 확인해야 할 위험이 있는가? |

자세한 사례는 `usecases/voc-mining.md`의 "하네스가 과한 경우" 절 참고.

---

## 6. 오늘 처음 만난 용어

| 용어 | 뜻 |
|---|---|
| 하네스 | 자연어 설명만으로 에이전트 팀을 자동으로 만들어 주는 도구(revfactory/harness) |
| 팀원(에이전트) | `.claude/agents/`에 파일 하나로 저장되는, 역할을 맡은 AI |
| 오케스트레이터 | 팀원들에게 순서대로 일을 시키는 팀장 역할의 스킬 |
| 검증 담당 (Producer-Reviewer) | 다른 팀원이 만든 결과를 의심하고 확인하는 역할 |
| 세션 | 하나의 대화창(터미널에서 `claude` 실행 후 `/clear`나 재실행 전까지) |
| 하네스 회고 | 실행 결과가 아쉬울 때 팀에게 말로 피드백해 팀을 진화시키는 것 |
| 마크다운 | 제목·표·목록을 기호 몇 개(`#`, `-`, `|` 등)로 표현하는 가벼운 문서 형식. 워드처럼 열리고 사내 위키에 붙여 넣기 좋다 |
