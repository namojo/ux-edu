# [슬라이드 개요] 반복 업무 하나를 나만의 AI 팀으로 (강사용)

> 완성된 슬라이드가 아니라 슬라이드별 제목 + 말할 요점입니다. 완성 슬라이드가 필요하면 이 개요를 바탕으로 pptx 스킬로 제작을 요청하세요.

---

### 슬라이드 1. 타이틀

- 제목: 반복 업무 하나를 나만의 AI 팀으로
- 부제: L3 · 90분 + 과제
- 말할 요점: 오늘은 "코드를 배우는 시간"이 아니라 "일을 나누는 법을 배우는 시간"임을 먼저 못박는다.

### 슬라이드 2. 지금까지 vs 오늘

- 좌: 지금까지 — 사례 1개를 대화 1번으로 처리 (VoC 분류, 페르소나 등)
- 우: 오늘 — 반복 업무 1개를 역할이 나뉜 팀으로 설계
- 말할 요점: "한 프롬프트로 다 끝내기"에서 "역할 분해 + 검증 단계"로 사고 전환이 오늘의 핵심.

### 슬라이드 3. 하네스란 무엇인가

- 정의: 역할이 나뉜 AI들이 순서대로 일하는 작은 팀. 사람은 검증 지점에서만 개입.
- 비유: 사람 팀과 똑같다 — 정리 담당, 분석 담당, 검수 담당이 따로 있는 것처럼.
- 말할 요점: "하네스"라는 용어를 오늘 처음 정의하고, 이후 계속 같은 뜻으로 쓴다고 안내.

### 슬라이드 4. 왜 역할을 나누는가

- 근거: 한 사람(또는 한 프롬프트)이 다 하면 검증을 스스로 건너뛰기 쉽다.
- 핵심 문장: "사람이 지겨워하지만 꼭 해야 하는 일(대조·확인)을 팀에게 맡기는 것이 하네스의 핵심 이점."
- 말할 요점: 지난 회차 사례들의 "한 걸음 더"에서 이미 이 패턴을 다뤘음을 상기시킨다.

### 슬라이드 5. (전환) 오늘 이 프로젝트 자체가 교재입니다

- 내용: 여러분이 배운 사례집·MVP·이 교육 자료 전부가 하네스 하나의 산출물.
- 말할 요점: 지금부터 그 하네스의 속을 직접 열어본다.

### 슬라이드 6. 실물 관찰 데모 — .claude/agents

- 화면: `.claude/agents/` 폴더 목록 (강사 화면 미러링)
- 말할 요점: 파일 하나 = 역할 하나. 5개 파일 = 5개 역할(사례 작성/자료 제작/설계/MVP 구현/검수).

### 슬라이드 7. 실물 관찰 데모 — 에이전트 정의 파일 하나 열기

- 화면: `ux-enablement-reviewer.md` 내용
- 강조 포인트 3개: 핵심 역할 / 입력·출력 프로토콜 / tools 제한(Edit·Write 없음 — 검증은 고치지 않는다)
- 말할 요점: "검증 담당은 만드는 사람과 분리된다"는 원칙이 실제 파일 설정으로 강제되어 있다.

### 슬라이드 8. 실물 관찰 데모 — 순서 확인

- 화면: `.claude/skills/ux-enablement/SKILL.md`의 워크플로우 표
- 말할 요점: 작성 → 검수 → (필요 시) 수정 → 재검수 순서. "동시에 다 하는 게 아니라 순서대로 이어받는다."

### 슬라이드 9. (전환) 이제 여러분 차례

- 내용: 실습 안내 — 반복 업무 1개 선정 → 사례 참고 → AI와 역할 브레인스토밍 → 캔버스 작성
- 말할 요점: 시간 배분(선정 5분 / 사례 읽기 5분 / 브레인스토밍 15분 / 캔버스 작성 20분) 안내.

### 슬라이드 10. 좋은 반복 업무 고르는 기준

- 체크리스트: 최근 3개월 내 2회 이상 / 여러 단계를 거침 / 결과물 형식이 매번 비슷함
- 말할 요점: "완전히 같은 일"이 아니라 "패턴이 비슷한 일"이면 충분하다고 안내(질문 대비).

### 슬라이드 11. 브레인스토밍 프롬프트 (화면에 띄워두기)

- 내용: guide.md Step 3의 복붙 프롬프트 전문을 그대로 슬라이드에 띄운다.
- 말할 요점: `{ }` 부분만 자기 업무로 바꾸면 된다. 검증 담당을 반드시 포함하라는 문장이 핵심이라고 짚어준다.

### 슬라이드 12. 검증 담당을 빼먹지 마세요

- 내용: 검증 담당이 빠진 예 vs 포함된 예 비교
- 말할 요점: AI가 검증 담당을 안 넣어줄 때의 대응법("검증 담당을 추가해서 다시 정리해줘") 미리 안내 — 실습 중 자주 나오는 질문.

### 슬라이드 13. 캔버스 완성 체크리스트

- 체크리스트: 역할 3~5개 / 검증 담당 포함 / 검증 방법 구체적 / 역할 간 입출력이 이어짐
- 말할 요점: 이 체크리스트로 짝과 서로 캔버스를 검토해 달라고 안내.

### 슬라이드 14. 공유

- 내용: 발표자 2~3명 — 업무명, 역할 개수, 검증 담당이 검증하는 것
- 말할 요점: 시간이 부족하면 전체 공유 대신 옆 사람과 1:1 공유로 축소 가능.

### 슬라이드 15. 과제 안내

- 내용: 다음 반복 주기에 캔버스대로 실제 업무 1회 실행 → 1~2주 뒤 산출물 리뷰에 캔버스 + 결과물 + 막힌 지점 가져오기
- 말할 요점: "완성된 하네스 파일"을 만들어 오라는 것이 아니라, 캔버스 순서대로 Claude Code에게 역할별로 순서대로 요청해 보는 것으로 충분하다고 안내 — 부담을 낮춘다.

### 슬라이드 16. 마무리 — 오늘 배운 것

- 요약 한 문장: "반복 업무는 한 프롬프트가 아니라, 역할이 나뉘고 검증이 들어간 팀으로 옮길 수 있다."
- 말할 요점: 프로그램 종료 설문 3문항(이번 주 실무에 쓸 것인가 / 가장 유용한 사례 / 막힌 지점) 안내로 연결.
