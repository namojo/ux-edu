## 3. 역할 분해 캔버스 (역할 3~5개)

> 반드시 역할 중 하나 이상을 "검증 담당"으로 채우세요. 검증 담당은 결과를 만드는 역할과 분리되어야 합니다.

| # | 역할 이름 | 받는 것 (입력) | 하는 일 | 넘기는 것 (출력) | 검증 담당인가 |

| 2 | | | | | ☐ 예 ☐ 아니오 |
| 3 | | | | | ☐ 예 ☐ 아니오 |
| 4 | | | | | ☐ 예 ☐ 아니오 |
| 5 | | | | | ☐ 예 ☐ 아니오 |

### 검증 담당 상세 (반드시 1개 이상 작성)

| 항목 | 내용 |
|------|------|
| 검증 담당의 역할 번호 (위 표의 #) | |
| 무엇을 검증하는가 (예: 인용문이 원문에 실제로 있는지, 개인정보가 남았는지, 근거 없는 추정이 섞였는지) | |
| 어떻게 검증하는가 (예: 원문 파일에서 Ctrl/Cmd+F로 검색해 대조) | |
| 검증에 걸리는 사람의 확인 시간 (대략) | |

## 4. 흐름 확인 (역할이 이어지는가)

각 역할의 "넘기는 것"이 다음 역할의 "받는 것"과 실제로 맞는지 화살표로 확인합니다.

```
1. ______________  →  2. ______________  →  3. ______________  →  4. ______________  →  5. ______________
```

체크리스트

- [ ] 역할이 3개 이상 5개 이하다
- [ ] 검증 담당이 최소 1개 포함되어 있다
- [ ] 검증 담당이 무엇을·어떻게 검증하는지 구체적으로 적혀 있다
- [ ] 앞 역할의 출력과 다음 역할의 입력이 서로 맞는다 (끊기는 지점이 없다)
- [ ] 최종 산출물(마지막 역할의 출력)이 실제로 내 업무에서 필요로 하는 결과물 형식과 같다
