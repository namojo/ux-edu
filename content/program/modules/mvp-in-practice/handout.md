# 핸드아웃 — MVP 수정 요청 문구 모음

> 모듈 `mvp-in-practice` 치트시트 · 책상에 두고 실습·업무 중 참고하세요 (1장)

시제품(`index.html`)이 만들어진 뒤, 마음에 안 드는 부분을 **말로** 고칠 때 쓰는 자연어 요청 예시 모음입니다. 아래 문구의 `{ }` 부분만 내 화면·요소로 바꿔서 Claude Code에 붙여넣으면 됩니다.

---

## 0. 모든 수정 요청 앞에 이 한 문장을 붙이세요

```
기존 화면 구조는 그대로 두고, 말한 부분만 고쳐줘.
```

이 문장이 없으면 AI가 필요 이상으로 다시 만들어 버릴 수 있습니다. 그러면 이전 버전과 비교가 불가능해집니다.

---

## 1. 요소·내용 추가

| 하고 싶은 것 | 요청 문구 예시 |
|---|---|
| 안내 문구 추가 | `{화면 이름}에 "{추가할 문구}" 안내를 눈에 띄게 추가해줘.` |
| 숫자/시간 정보 추가 | `{화면 이름}에 예상 {픽업 시간/소요 시간}을 대기번호 옆에 추가해줘.` |
| 버튼 추가 | `{화면 이름}에 "{버튼 문구}" 버튼을 추가하고, 누르면 {어디로} 이동하게 해줘.` |
| 뒤로가기/홈 버튼 추가 | `{화면 이름}에 뒤로가기 버튼이 없어. 이전 화면으로 돌아갈 수 있게 추가해줘.` |

## 2. 스타일·비주얼 바꾸기

| 하고 싶은 것 | 요청 문구 예시 |
|---|---|
| 밋밋한 화면 꾸미기 | `{화면 이름}이 너무 밋밋해. 각 항목에 이모지를 넣고, 선택하면 색이 진해지게 해줘.` |
| 강조 크기 키우기 | `{요소 이름}을 더 크고 눈에 띄게 강조해줘.` |
| 색/톤 바꾸기 | `전체적으로 색 톤을 {차분한 파란 계열}로 바꿔줘. 레이아웃은 그대로 두고.` |
| 카드/배지 강조 | `{카드 이름}마다 {가격/상태} 뱃지를 더 크게 보여줘.` |

## 3. 흐름·화면 구조 바꾸기

| 하고 싶은 것 | 요청 문구 예시 |
|---|---|
| 화면 나누기 | `{화면 이름}이 너무 복잡해. {A 부분}과 {B 부분}을 별도 화면 2개로 나눠줘.` |
| 화면 합치기 | `{화면 이름}과 {화면 이름}을 한 화면으로 합쳐줘. 클릭 한 번으로 다음까지 가게.` |
| 선택 방식 바꾸기 | `{화면 이름}의 선택 방식을 {단일 선택}에서 {복수 선택}으로 바꿔줘.` |
| 단계 추가 | `{화면 A}와 {화면 B} 사이에 {새 화면 목적}을 확인하는 화면을 하나 추가해줘.` |

## 4. 데이터·더미 값 바꾸기

| 하고 싶은 것 | 요청 문구 예시 |
|---|---|
| 더미 데이터 현실감 높이기 | `{항목}에 들어간 더미 데이터가 티가 나. 실제로 있을 법한 한국어 값으로 다시 채워줘.` |
| 특정 값 고정 | `{항목} 값을 항상 "{고정하고 싶은 값}"으로 보여줘.` |

## 5. 점검 요청 (수정이 아니라 확인)

| 확인하고 싶은 것 | 요청 문구 예시 |
|---|---|
| 막다른 화면 유무 | `모든 버튼이 어딘가로 연결되는지 확인해서, 막다른 화면이 있으면 알려줘.` |
| 접근성 | `이 화면들 색 대비랑 키보드 조작 접근성 관점에서 문제 있는 곳 짚어줘.` |
| 현재 파일 위치 | `지금 만들어진 index.html이 어느 폴더에 있는지 알려줘.` |
| 브라우저로 열기 | `방금 만든(또는 수정한) 프로토타입을 브라우저에서 열어줘.` |

---

## 자주 막히는 지점 3가지

> 💡 **권한 확인 창이 떴다**
> 정상입니다. 내가 요청한 작업(파일 생성·수정)을 실행해도 되는지 묻는 것입니다. **허용**을 선택하세요.

> 💡 **더블클릭했는데 코드처럼 보인다**
> 브라우저가 아니라 텍스트 편집기로 열렸습니다. 파일 우클릭 → 연결 프로그램 → 브라우저(Chrome/Safari/Edge)로 다시 여세요.

> 💡 **새로고침해도 수정 내용이 안 보인다**
> 파일이 다른 폴더에 새로 만들어졌을 수 있습니다. `지금 만들어진 index.html이 어느 폴더에 있는지 알려줘`라고 물어보세요.

---

## 잊지 말 것

- 수정할 때마다 **"기존 화면 구조는 그대로 두고"**를 꼭 붙이세요.
- 이 시제품은 **테스트 도구**입니다 — "잘 되니까 출시"가 아니라 "흐름을 검증했으니 제대로 개발"이 다음 단계입니다.
- 더미 데이터는 전부 지어낸 값입니다. 참가자·이해관계자에게 보여줄 땐 "실제 데이터 아님"을 알려주세요.
