# 실습 가이드 — Claude Code 열고 하네스 설치까지

| 항목 | 내용 |
|------|------|
| 레벨 / 시간 | L1 / 90분 (도입·예시 30분 — 실습 45분 — 공유·정리 15분) |
| 선수 조건 | 없음. 단, **Claude Code가 노트북에 설치되어 있어야** 합니다(미설치자는 도입 30분에 먼저 설치). |
| 준비물 | 노트북, `sample-reviews.txt`(함께 제공되는 리뷰 20건 샘플 파일) |
| 오늘의 목표 | 터미널을 열고 → 작업 폴더로 이동해 `claude`를 켜고 → 폴더 안 파일을 읽혀 첫 결과를 받는다. 그리고 **revfactory/harness 플러그인을 설치**해 다음 모듈에서 팀을 만들 준비를 끝낸다. |

> 이 문서에서 "Claude Code"는 오늘 쓸 AI 도구의 이름입니다. 터미널(명령어를 입력하는 검은/흰 창)에서 `claude`라는 명령어로 켭니다. "하네스"는 여러 AI 팀원(에이전트)과 그들이 따르는 작업 방법을 한 번에 만들어 주는 도구(revfactory/harness)를 가리키는 말입니다. 앞으로 이 자료에서는 도구 이름은 "Claude Code", 켜는 명령어는 `claude`, 팀 만들기 도구는 "하네스"로 통일해서 씁니다.

> 오늘 모듈은 하네스를 **설치**까지만 합니다. 팀을 실제로 만드는 것(구성)은 다음 모듈 `first-harness`에서 합니다 — 오늘은 "AI 도구 다루기"가 목적이 아니라 **하네스로 가는 최소 진입 계단**입니다.

---

## 0. 시작 전 확인 (5분)

터미널을 처음 본다면 아래 체크리스트를 먼저 훑어보세요. (터미널을 여는 자세한 방법은 2단계에서 다시 다룹니다.)

☐ 노트북에 Claude Code가 설치되어 있다 (터미널에 `claude`라고 쳤을 때 뭔가 반응이 있으면 설치된 것)
☐ **`claude` 실행 시 로그인/계정 인증까지 이미 끝나 있다** (도입 설치 과정에서 계정 로그인까지 완료했는지 직접 확인합니다)
☐ 안 되어 있다면 지금 바로 설치·로그인부터 마칩니다.
☐ 함께 제공되는 `sample-reviews.txt` 파일을 다운로드/전달받았다 (USB, 메신저 파일 전송, 또는 사내 공유 폴더)

> 💡 **이렇게 나오면 정상입니다: 터미널에 `claude`를 쳤는데 "command not found"가 뜬다**
> → 아직 설치가 안 됐거나, 터미널을 재시작해야 인식되는 경우입니다. 터미널을 완전히 닫았다 다시 열어 한 번 더 시도해 보세요. 그래도 안 되면 에러 메시지를 그대로 복사해 Claude Code에 붙여넣고 "이 에러 어떻게 해결해?"라고 물어보거나, 사내 헬프 채널에 문의하세요.

# 도입 단계 — 먼저 훑어보기 (30분)

## 1단계. 바탕화면에 작업 폴더 만들기

**"작업 폴더"**는 오늘 우리가 쓸 파일들을 모아두는 전용 폴더입니다. Claude Code는 **지금 열려 있는 폴더 안의 파일만** 읽고 씁니다. 그래서 매번 "이번 작업용 폴더"를 하나 만들고 그 안에서 시작하는 습관을 들입니다.

1. 바탕화면(Desktop)에서 마우스 우클릭 → **새로운 폴더(New Folder)**
2. 폴더 이름을 알아보기 쉽게 정합니다. 오늘은 `first-contact-lab` 으로 통일하겠습니다.
3. 함께 제공되는 `sample-reviews.txt` 파일을 이 폴더 **안으로** 옮겨 넣습니다(드래그앤드롭 또는 복사-붙여넣기).

> 💡 **이렇게 나오면 정상입니다: 파일이 다운로드 폴더에 있는데 어떻게 옮기는지 모르겠다**
> → Finder(파일 탐색기) 창을 하나 더 열어(Cmd+N) 다운로드 폴더와 바탕화면 폴더를 나란히 띄우고 파일을 끌어다 놓으면 됩니다.

---

## 2단계. 터미널 열기

터미널은 마우스 대신 **글자로 명령을 입력해 컴퓨터를 조작하는 창**입니다. 오늘은 딱 두 가지 방법 중 편한 것으로 엽니다.

**방법 B — 터미널을 먼저 켜고 `cd`로 이동하기 (기본 추천)**
1. Spotlight(Cmd+Space)에서 "터미널"(영문 환경이면 "Terminal")이라고 검색해 실행
2. `cd `(cd 뒤에 띄어쓰기 한 번) 까지만 입력한 상태에서, **바탕화면의 `first-contact-lab` 폴더를 터미널 창 위로 드래그앤드롭**합니다. 폴더 경로가 자동으로 입력됩니다.
3. Enter를 누릅니다.

**방법 A — 폴더에서 바로 열기 (메뉴가 이미 켜져 있는 경우에만)**
1. 방금 만든 `first-contact-lab` 폴더를 마우스 우클릭
2. 메뉴에서 **"폴더에서 새 터미널 열기(New Terminal at Folder)"** 클릭
   - 안 보이면 메뉴 맨 아래 **"더 보기(More)"** 안에 있을 수 있습니다.
3. 검은/흰 창(터미널)이 뜨면, 이미 우리 작업 폴더 안에 들어와 있는 상태입니다.

> 💡 **이렇게 나오면 정상입니다: 우클릭 메뉴에 "폴더에서 새 터미널 열기"가 아예 안 보인다**
> → macOS는 이 메뉴가 **기본값으로 꺼져 있는 경우가 더 많습니다.** 설정(시스템 설정 > 키보드 > 단축키 > 서비스)에서 따로 켜야 보이므로, 안 보이는 게 오히려 정상입니다. 시간 끌지 말고 바로 위 **방법 B**로 진행하세요.

> 💡 **이렇게 나오면 정상입니다: `cd` 이후 Enter를 눌렀는데 에러 문구(빨간 글씨, "No such file or directory")가 뜬다**
> → 경로에 오타가 있거나 띄어쓰기가 잘못 들어간 경우입니다. 방금 입력한 줄을 지우고(백스페이스), 폴더를 다시 드래그앤드롭해서 새로 입력하세요. 직접 타이핑보다 드래그앤드롭이 훨씬 안전합니다.

**내가 올바른 폴더 안에 들어왔는지 확인하는 법**: 터미널에 `ls`를 입력하고 Enter. `sample-reviews.txt`가 목록에 보이면 성공입니다.

```
ls
```

> 💡 **이렇게 나오면 정상입니다: `ls`를 쳤는데 아무 파일도 안 보인다 (또는 `sample-reviews.txt`가 없다)**
> → 아직 다른 폴더에 있는 상태입니다. 1단계에서 파일을 정말 `first-contact-lab` 폴더 "안에" 넣었는지 Finder에서 다시 확인하고, 2단계를 처음부터 다시 하세요.

---

## 3단계. Claude Code 켜기

터미널에 아래와 같이 입력하고 Enter를 누릅니다.

```
claude
```

몇 초 기다리면 화면이 바뀌면서 Claude Code 대화창이 나타납니다. 이제부터 여기에 원하는 것을 **한국어 문장으로** 입력하면 됩니다.

`claude`를 처음 켤 때는 아래 화면들이 **순서대로** 나타날 수 있습니다. 당황하지 말고 하나씩 넘어가세요.

> 💡 **이렇게 나오면 정상입니다: 로그인/계정 화면이 나온다**
> → 사전에 계정 인증이 끝나지 않은 상태입니다. **이 화면은 기본값으로 그냥 넘길 수 없습니다** — 실제 계정 로그인이 필요한 화면입니다. 화면에 나온 안내(보통 브라우저가 열리며 로그인 절차가 시작됩니다)를 그대로 따라가세요. 막히면 화면의 안내 문구나 에러 메시지를 그대로 복사해 검색하거나, 사내 헬프 채널에 문의하세요. (0단계에서 설치 시 로그인까지 끝냈어야 하는 부분입니다.)

> 💡 **이렇게 나오면 정상입니다: "Do you trust the files in this folder?"(이 폴더의 파일을 신뢰합니까?) 같은 신뢰 확인 화면이 나온다**
> → Claude Code가 처음 보는 폴더에서 실행될 때 한 번 묻는 화면입니다. 지금 폴더는 오늘 우리가 직접 만든 연습용 폴더이므로, **"Yes, proceed"(예, 진행합니다)** 를 선택하고 Enter를 누르면 됩니다.

> 💡 **이렇게 나오면 정상입니다: 언어·테마 등을 묻는 초기 설정 화면이 나온다**
> → 처음 실행 시 한 번만 나오는 화면입니다. 방향키나 숫자로 항목을 고르고 Enter로 다음으로 넘어가면 됩니다(기본값 그대로 진행해도 무방).

여기까지가 도입 단계입니다. 이제부터는 각자 속도로 진행하는 실습 단계입니다 — 막히면 에러 메시지를 그대로 복사해 Claude Code에 붙여넣고 "이 에러 어떻게 해결해?"라고 물어보세요.

# 실습 단계 — 각자 진행 (45분)

## 4단계. 첫 프롬프트 — 파일을 읽혀서 요약받기

**"프롬프트"**란 우리가 AI에게 입력하는 요청 문장을 말합니다. 오늘부터 이 자료에서는 이 말을 그대로 씁니다.

Claude Code 대화창에 아래 문장을 그대로 입력하고 Enter를 누르세요. (복사-붙여넣기 가능)

```
sample-reviews.txt 파일을 읽고 무슨 내용인지 3줄로 요약해줘.
```

입력하고 나면 화면에 파일을 읽는 과정이 잠깐 보이다가, 이어서 요약 결과가 나타납니다.

> 💡 **이렇게 나오면 정상입니다: 파일 접근 권한을 확인하는 창(Allow? / 허용하시겠습니까?)이 뜬다**
> → Claude Code는 내 컴퓨터의 파일을 읽거나 실행하기 전에 "정말 이 폴더의 이 작업을 해도 되는지" 사람에게 확인을 받도록 되어 있습니다. 이유: AI가 마음대로 파일을 손대지 않도록 하는 안전장치입니다. 이 창이 **뜰 수 있고**, 뜨면 이렇게 대응합니다.
> - 화면에 보통 `1. Yes` / `2. Yes, and don't ask again` / `3. No` 같은 선택지가 나옵니다.
> - 지금은 우리가 만든 연습용 폴더이므로 **`1. Yes`** (한 번만 허용)를 선택하고 Enter를 누르면 됩니다.
> - 이 창이 뜨는 것 자체가 **정상이고 오히려 안전하게 작동하고 있다는 신호**입니다. 놀라지 않아도 됩니다.

> 💡 **이렇게 나오면 정상입니다: 권한 확인 창 없이 바로 요약 결과가 나온다**
> → 이것도 정상입니다. 단순히 파일을 "읽기"만 하는 작업은 설정이나 버전에 따라 확인 창이 생략되고 곧바로 결과가 나오는 경우가 흔합니다. 특히 3단계에서 "이 폴더를 신뢰합니까?"에 이미 `Yes, proceed`로 답했다면 더욱 그렇습니다. **다른 사람의 화면과 다르게 나와도 내 화면이 잘못된 것이 아닙니다** — 둘 다 정상적인 결과입니다.

> 💡 **이렇게 나오면 정상입니다: 결과가 영어로 나온다**
> → 드물게 발생합니다. 당황하지 말고 `한국어로 다시 대답해줘`라고 이어서 입력하면 됩니다.

> 💡 **이렇게 나오면 정상입니다: 오타를 냈다 / Enter를 잘못 눌렀다**
> → 대화창은 채팅과 같아서 잘못 보내도 괜찮습니다. 다음 줄에 다시 정확한 문장을 입력해 보내면 됩니다. 되돌리기 걱정 없이 편하게 입력하세요.

## 5단계. 결과 확인

화면에 뜬 요약을 소리 내어 읽어봅니다. 3줄로 요약이 됐는지, 리뷰 20건의 전체적인 느낌(배달 지연, 결제 오류, 만족 후기 등)이 잘 담겼는지 눈으로 확인합니다.

> 지금 단계에서는 **결과가 완벽히 정확한지 검증하지 않습니다.** "AI가 파일을 읽고 뭔가 그럴듯한 결과를 돌려준다"는 감각을 익히는 것이 오늘의 목표입니다. 결과를 의심하고 검증하는 습관은 다음 모듈 `first-harness`에서 하네스에 **검증 담당 팀원**을 두는 구조로 배웁니다.

---

## 6단계. 후속 요청 — 대화가 이어진다는 것 체감하기

Claude Code는 이전 대화 내용을 기억한 채로 이어서 대화할 수 있습니다. 방금 받은 요약을 다른 형태로 다시 요청해봅니다.

```
방금 요약을 표로 다시 보여줘.
```

방금 받은 3줄 요약이 이번엔 표(항목/내용 같은 형태) 모양으로 다시 정리되어 나오는 것을 확인합니다.

> 💡 **이렇게 나오면 정상입니다: "방금"이 무엇을 가리키는지 못 알아듣는 것 같다**
> → 아주 드물게, 이전 요청과 너무 다른 새 대화처럼 반응할 때가 있습니다. 이럴 땐 `방금 sample-reviews.txt 요약해준 내용을 표로 다시 보여줘`처럼 무엇을 가리키는지 조금 더 구체적으로 적어주면 됩니다.

이 단계가 파일 다루기 실습의 핵심 체험입니다: **한 번 던지고 끝나는 게 아니라, 이어서 다듬을 수 있다**는 감각을 몸에 익히는 것.

---

## 7단계. 하네스 설치 — 다음 모듈에서 팀을 만들 준비

지금까지는 Claude Code 혼자에게 요청을 던졌습니다. 다음 모듈(`first-harness`)부터는 **여러 AI 팀원(에이전트)이 역할을 나눠 일하는 팀**을 말 한마디로 만들게 됩니다. 그 팀을 만들어 주는 도구가 **하네스(revfactory/harness)** 입니다. 오늘은 이 도구를 설치까지만 해둡니다.

Claude Code 대화창에 아래 두 줄을 **차례로** 입력하고 Enter를 누르세요. (복사-붙여넣기 가능, 한 줄씩 따로 입력합니다)

```
/plugin marketplace add revfactory/harness
```

```
/plugin install harness@harness-marketplace
```

> 💡 **이렇게 나오면 정상입니다: 설치 명령을 입력했는데 화면에 진행 상황이 뜨고 잠시 멈춰 있는 것 같다**
> → 마켓플레이스를 등록하고 플러그인을 내려받는 동안 몇 초~수십 초 정도 걸릴 수 있습니다. 화면이 멈춘 게 아니라 **설치가 진행 중인 것이 정상**입니다. 다시 엔터를 누르거나 창을 닫지 말고 기다려주세요.

> 💡 **이렇게 나오면 정상입니다: 이미 설치되어 있다는 메시지가 뜬다**
> → 이전에 같은 노트북에서 설치를 시도한 적이 있는 경우입니다. 오류가 아니라 "이미 설치됨" 안내이니 다음 단계(설치 확인)로 넘어가면 됩니다.

> ⚠️ **이럴 땐 이렇게: 빨간 글씨의 에러/실패 메시지가 뜬다**
> → 사내망·방화벽이 GitHub 접근을 막고 있는 경우일 수 있습니다("이미 설치됨"과는 다른, 실패를 알리는 문구입니다). 에러 메시지를 그대로 복사해 Claude Code에 붙여넣고 "이 에러 어떻게 해결해?"라고 물어보세요. 그래도 해결이 안 되면 사내 헬프 채널에 문의하세요 — 네트워크 환경 문제는 개인이 고칠 수 없는 경우가 많습니다.

**설치가 되었는지 확인하는 법**: 두 번째 명령(`/plugin install harness@harness-marketplace`) 실행 후 화면에 설치 완료를 알리는 메시지가 나타나는지 확인합니다. 확인이 애매하면 아래처럼 플러그인 목록을 직접 열어봅니다.

```
/plugin
```

플러그인 관리 화면이 열리고 목록에 `harness`가 보이면 설치가 끝난 것입니다. 여기서 나가려면 Esc를 누르면 됩니다.

> 💡 **오늘은 여기까지입니다.** "하네스 구성해줘"로 실제 팀을 만드는 것은 다음 모듈 `first-harness`에서 합니다. 오늘은 설치 확인 메시지까지 도달하면 성공입니다.

## 참고 — Windows 사용자라면

이 실습은 macOS Finder 기준으로 작성했습니다. Windows에서는 아래로 대체하세요.

- 폴더 우클릭 → **"터미널에서 열기"** (없으면 폴더 안에서 주소 표시줄에 `cmd`를 입력하고 Enter)
- `cd` 뒤에 폴더를 드래그앤드롭하는 방식은 Windows 터미널에서도 동일하게 동작합니다.
- **cmd 창에서는 `ls` 대신 `dir`을 입력해 목록을 확인하세요**(PowerShell은 `ls`도 됩니다). 일반 `cmd`에서 `ls`를 치면 "'ls' is not recognized" 에러가 나는데, 잘못한 게 아니라 명령어가 다른 것뿐입니다.

> 💡 **중요: 반드시 Claude Code를 설치할 때 사용한 것과 같은 터미널을 여세요**
> → Windows는 설치 방식(PowerShell / WSL / Git Bash 등)에 따라 `claude` 명령이 특정 터미널에서만 인식될 수 있습니다. 일반 `cmd` 창에서 `claude`를 쳤는데 "command not found"(또는 인식할 수 없다는 메시지)가 뜨면 고장이 아니라 **다른 터미널을 열어야 하는 신호**입니다 — 설치 때 사용한 터미널을 열어 다시 시도하세요. 실습 시작 전 내가 어떤 터미널로 설치했는지 스스로 한 번 확인해 두면 좋습니다.

막히면 에러 메시지를 그대로 복사해 Claude Code에 붙여넣고 "이 에러 어떻게 해결해?"라고 물어보세요. 해결이 안 되면 사내 헬프 채널에 문의하세요. `/plugin` 관련 명령어는 운영체제와 무관하게 Claude Code 대화창 안에서 동일하게 동작합니다.
